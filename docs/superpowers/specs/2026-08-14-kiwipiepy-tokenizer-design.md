# 어휘 토크나이저 — 규칙 기반에서 kiwipiepy 로

> 작성일: 2026-08-14
> 대상: `core/lexical.py`, 새 어댑터 `adapters/tokenizer/`, `adapters/lexical/sqlite.py`, `main.py`
> 이 문서가 되돌리는 것: `openspec/changes/archive/2026-08-04-add-rrf-algorithm-spec` 의 **결정 2**
> (토큰화는 순수 파이썬 규칙으로 한다).

## 왜 이 문서가 있는가

`add-rrf-algorithm-spec` 결정 2 는 형태소 분석기를 **의도적으로 기각**했다. 근거는 의존성
비용이었다 — `konlpy` 는 JVM 을, `mecab` 은 C 확장 + 사전 데이터를 요구해 이미지가 수백 MB
늘고 빌드가 플랫폼을 탄다. 그 대신 순수 파이썬 규칙 토크나이저(정규화·경계 분할·접미 벗기기)를
두고, 규칙 기반의 과벗김은 "원 토큰과 어근을 둘 다 색인"·"희소도 하한"·"RRF 융합" 세 그물로
흡수했다.

이 문서는 그 결정을 되돌린다. **`kiwipiepy` 는 기각의 근거였던 세 비용(JVM·별도 사전·플랫폼
의존)을 대부분 해소한다** — 순수 pip 설치(prebuilt wheel), 모델이 동반 패키지로 번들되어
런타임 다운로드가 없고, C++ 코어라 JVM 이 필요 없다. 과벗김을 흡수하려 얹었던 근사 장치가
사라지고 토큰화 품질이 오른다.

되돌리는 이유를 남기는 것이 요구사항이다 — `CLAUDE.md` 「문서-코드 일치」와 「도중에 기술
선택을 바꿨다면 바꾼 이유를 문서에 남겨라(그쪽이 가산점)」에 따른다.

## 무엇을 바꾸지 않는가

- **FTS5 어휘 색인의 구조** — `chunks` 가상 테이블, `tokens` 컬럼에 공백으로 이어 붙인 토큰,
  `unicode61 remove_diacritics 0`, `fts5vocab` 희소도 계산. 토크나이저가 내는 토큰 문자열만
  달라지고 그것을 담는 그릇은 그대로다.
- **희소도 하한·RRF 융합·리랭킹** — 검색 파이프라인의 뒷단은 손대지 않는다.
- **쓰기와 읽기가 같은 토크나이저를 쓴다는 규약** — 색인과 질의가 같은 구성을 봐야 한다.
  구성이 갈리면 오류 없이 아무것도 매칭하지 않는다.

## 설계

### 1. 계층 구조 — `core/` 순수성을 어댑터 격리로 지킨다

`core/` 는 표준 라이브러리만 쓴다(`ARCHITECTURE.md` 원칙). `kiwipiepy` import 는 이 경계를
깨므로 어댑터로 격리한다.

- `core/lexical.py` 에 **`Tokenizer` 프로토콜**을 정의한다 — 구조적 인터페이스로
  `tokenize(text: str) -> tuple[str, ...]` 와 `signature_material -> str` 둘을 요구한다.
- 기존 규칙 기반 구현은 **`RuleTokenizer` 로 남긴다.** 표준 라이브러리라 모델 로드 없이 돌고,
  테스트 기본값·폴백 후보로 쓸모가 있다. 지우지 않는다.
- 새 어댑터 `adapters/tokenizer/kiwi.py` 가 `kiwipiepy` 로 프로토콜을 구현한다. **`kiwipiepy`
  import 는 이 파일에만 존재한다.**
- `main.py` 가 기본 토크나이저를 Kiwi 어댑터로 배선한다(`DEFAULT_TOKENIZER` 대체).

`adapters/lexical/sqlite.py` 는 이미 `Tokenizer` 를 주입받아 `.tokenize()` 만 부르므로
(현재 `SqliteLexicalIndex.__init__(tokenizer=...)`), 구현체를 바꿔 끼우는 것으로 끝난다 —
소비처 코드는 프로토콜만 본다.

### 2. 토큰화 로직 (어댑터)

`kiwi.tokenize(text)` 가 내는 형태소 중 **내용어 태그만** 유지한다.

- 유지: `NNG`·`NNP`(명사), `VV`·`VA`(동사·형용사 — kiwipiepy 가 어간 형태로 반환),
  `XR`(어근), `SL`(외국어), `SN`(숫자), `SH`(한자).
- 버림: 조사(`JK*`·`JX`), 어미(`E*`), 기호(`S[FEPS...]`), 그 밖의 기능 형태소.
- `SL`(라틴)은 casefold 로 정규화해 질의와 정렬한다. 숫자·명사는 형태 그대로.
- 중복 토큰은 유지한다 — BM25 의 빈도(TF) 항이 그것을 읽는다.

규칙 기반의 근사 장치는 **형태소 분석에 흡수되어 사라진다**:
- 경계 분할(`"200만원"` → `200`·`만원`): kiwipiepy 가 `200`/`만`/`원` 으로 이미 나눈다.
- 접미 벗기기(조사·어미 사전): 형태소 분석이 정확히 한다.
- 원형+어근 병기(재현율 보수): 과벗김이 드물어져 이중 색인이 불필요하다.

### 3. 재색인 (index_signature)

Kiwi 어댑터의 `signature_material` 에 **토크나이저 버전 상수 + kiwipiepy 모델 버전 + 유지하는
POS 태그 집합**을 넣는다. 이 값이 `derive_index_signature` 의 `tokenizer_signature` 재료가
되므로, 분석기나 태그 집합이 바뀌면 서명이 달라지고 기존 문서가 `stale` 이 된다. **기존 기동
정리 경로가 그대로 처리한다** — 새 무효화 메커니즘을 만들지 않는다. 배포 후 재업로드가 대가다.

### 4. 의존성·빌드

- `pyproject.toml` 에 `kiwipiepy` 를 추가한다. 모델은 동반 패키지(`kiwipiepy_model`)로 wheel 에
  번들되어 **런타임 네트워크 다운로드가 없다** — `CLAUDE.md` 의 "레이아웃/모델을 첫 사용 시점에
  받으면 평가자 첫 업로드가 네트워크에 묶인다" 함정을 피한다.
  **구현 1.1 에서 컨테이너로 이 번들 여부를 실측 검증한다**(설치 목록에 `kiwipiepy_model` 이
  들어오는지, 첫 `tokenize` 가 네트워크 없이 끝나는지).
- Dockerfile 설치 레이어에 포함한다. 기동 시 Kiwi 인스턴스를 warm-up 한다 — 임베더·리랭커의
  지연 로딩+락 패턴과 동일하게, 첫 요청이 모델 로드를 물지 않게 한다.

### 5. 에러 핸들링

**조용한 폴백을 두지 않는다.** `kiwipiepy` import 나 모델 로드가 실패하면 첫 사용에서 도메인
예외로 드러낸다 — `SqliteLexicalIndex._ensure_schema` 가 `fts5_is_available()` 실패를 빈 결과로
위장하지 않고 `StorageUnavailable` 로 세우는 것과 같은 철학이다. 빈 결과로 위장하면 "토크나이저가
꺼진 채 도는 것"과 "매칭이 정말 없는 것"이 구별되지 않는다.

### 6. 테스트

- **검색 계약 테스트는 `RuleTokenizer` 로** 유지한다. 토크나이저가 주입식이라 가능하다 —
  빠르고 모델 로드가 없어 핵심 3경로(ingestion·retrieval·캐시 무효화) 테스트가 kiwipiepy 설치에
  묶이지 않는다.
- **Kiwi 어댑터 전용 테스트**를 더해 POS 매핑을 검증한다: 조사·어미가 버려지는지, 동사 어간이
  남는지, `SL`·`SN` 이 유지되는지. 모델 로드가 무거우면 `redis` 마커처럼 별도 마커 뒤로 격리하는
  것을 검토한다(기본 실행에서 빠지되, 명시 실행으로 돌아간다).
- 기존 `test_lexical`·`test_parsers` 중 **Kiwi 기본 배선을 전제한 토큰 단언**이 있으면 갱신한다.
  단언이 `RuleTokenizer` 를 주입해 쓰던 것이면 그대로 둔다.

### 7. 문서

- 이 설계 문서를 커밋한다.
- `ARCHITECTURE.md` 「어휘 색인」에 "규칙 기반 → kiwipiepy 로 교체, 이유(기각 근거 해소)"를
  적고, 규칙 기반 시절의 실측표(희소도 하한 등)가 여전히 유효한지 표시한다.
- `add-rrf-algorithm-spec` 결정 2 에 되돌림 표지를 남긴다 — 채택 이유가 아니라 **되돌린 이유**가
  다음 사람을 막는다.

## 트레이드오프

| 축 | 규칙 기반(현재) | kiwipiepy(변경 후) |
|---|---|---|
| 토큰화 품질 | 낮음(과벗김) | 높음 |
| 이미지 크기 | +0 | +수십 MB(모델 포함) |
| 기동 시간 | 0 | +모델 로드(수백 ms, warm-up) |
| 빌드 이식성 | 완벽(표준 라이브러리) | prebuilt wheel 의존 |
| `core/` 순수성 | 유지 | **어댑터 격리로 유지** |
| 근사 장치 | 필요(3중 그물) | 불필요(분석기가 흡수) |

핵심 판단: "정확한 토큰화"의 이득을 택하되, `kiwipiepy` 가 기각의 근거였던 의존성 비용을 이미
대부분 해소하므로 원래 트레이드오프의 무게추가 바뀌었다. `core/` 순수성은 어댑터 격리로 지키고,
품질 손실을 흡수하던 장치(원형+어근 병기)는 형태소 분석이 대신한다.

## 미해결·검증 대상

- **kiwipiepy 모델 번들 실측** — wheel 에 모델이 포함되어 런타임 다운로드가 없음을 컨테이너에서
  확인(구현 1.1). 별도 다운로드가 필요하면 빌드 단계로 옮긴다.
- **동시성** — Kiwi 인스턴스 하나를 스레드풀에서 공유해 `tokenize` 를 동시 호출하는 것이
  안전한지 확인한다. 수집이 스레드풀에서 도므로(임베더와 같은 자리), 안전하지 않으면 인스턴스
  풀이나 락이 필요하다.
- **POS 태그 집합의 경계** — `MAG`(일반부사)·`VX`(보조용언) 등을 유지 목록에 넣을지는
  `sample-docs/` 회귀 질의로 실측해 정한다. 초안은 명사·동사·형용사·어근·외국어·숫자·한자다.
