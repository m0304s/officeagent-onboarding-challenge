# 미검증 가정 (스파이크 목록)

구현은 했지만 **실제로 동작하는지 확인하지 않은** 것들을 모아둔 곳입니다. 적어두지 않으면 조용히 사라지고, 마감에 가까워서 발견하면 되돌릴 시간이 없습니다.

각 항목은 그것을 처음 필요로 하는 change의 **첫 태스크**로 옮겨집니다. 확인이 끝나면 결과(사실이었는지, 아니었는지)를 적고 여기서 지웁니다.

## S-1. 컨테이너 안에서 LLM CLI가 실제로 답변을 생성하는가

- **담당 change**: QA (답변 생성)
- **현재 상태**: 이미지에 CLI가 설치돼 있고(`claude 2.1.220` 실행 확인), 자격증명 파일이 컨테이너 안에서 읽고 쓸 수 있는 것까지 확인. **호출은 해 본 적 없음.**
- **확인 방법**: 컨테이너 안에서 `claude -p "1+1"` 수준의 최소 호출 1회.
- **틀렸을 경우**: 호스트 실행 모드를 문서화된 실행 경로로 승격하고 `README.md`·`ARCHITECTURE.md`를 함께 수정. 차선은 Codex CLI 전환 (design 결정 5-1 대안 3 — 자격증명이 평문 파일이라 호스트와 같은 파일을 공유할 수 있지만, 파이썬 SDK가 없어 스트리밍·timeout·retry를 직접 구현해야 함).

## S-2. 마운트한 자격증명을 컨테이너 안의 CLI가 인증에 쓰는가

- **담당 change**: QA (S-1과 같은 호출로 함께 확인)
- **현재 상태**: macOS Keychain 블롭의 구조가 Linux `.credentials.json`과 동일하다는 것, 그리고 그 파일이 컨테이너 안 `/home/app/.claude/.credentials.json`에 0600·`app` 소유로 보인다는 것까지 확인. **CLI가 그 경로에서 읽어 인증에 성공하는지는 미확인.**
- **확인 방법**: S-1의 호출이 인증 오류 없이 통과하는지.
- **틀렸을 경우**: CLI가 기대하는 경로·포맷을 `claude` 진단 출력으로 확인해 마운트 지점을 조정.

## S-3. refresh token이 회전해 호스트 CLI가 로그아웃되는가

- **담당 change**: QA
- **현재 상태**: 컨테이너가 가진 것은 **사본**이다(design 결정 5-1). 갱신 시 refresh token이 회전하는 방식이면 호스트 Keychain의 값이 무효가 되어 호스트 CLI가 로그아웃될 수 있다. **회전 여부 미확인.**
- **확인 방법**: 컨테이너를 access token 만료(실측 약 8시간)를 넘겨 띄워 둔 뒤, 사본의 `refreshToken`이 바뀌었는지와 호스트 CLI가 여전히 동작하는지 확인.
- **완화책(이미 적용)**: 기동할 때마다 재추출해 사본이 묵는 창을 컨테이너 수명으로 제한. 실행 세션이 8시간보다 짧으면 갱신 자체가 잘 일어나지 않음.
- **틀렸을 경우**: 호스트 재로그인이 필요하다는 경고를 `README.md`에 이미 적어 둠. 빈발하면 자격증명을 읽기 전용으로 붙이고 짧은 세션만 지원하는 쪽으로 후퇴.

## S-4. 호스트 UID가 1000이 아닌 리눅스에서 자격증명 마운트가 읽히는가

- **담당 change**: QA 또는 배포 정리
- **현재 상태**: macOS(Docker Desktop)에서만 확인. macOS는 바인드 마운트 소유권을 컨테이너 사용자로 매핑해 주지만, 리눅스는 호스트 UID가 그대로 보인다. 자격증명 파일이 0600이라 UID가 다르면 **읽지 못한다.**
- **확인 방법**: 리눅스 호스트(UID≠1000)에서 `make up` 후 컨테이너 안에서 파일 읽기.
- **완화책(이미 적용)**: `docker-compose.yml`에 `user:` 오버라이드 줄을 주석으로 넣어 두고 `README.md`에 안내. **주석을 풀었을 때 실제로 해결되는지는 미확인.**
