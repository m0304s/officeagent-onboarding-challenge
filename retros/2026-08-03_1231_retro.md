- **README의 `/search` 예시가 세 회고째 손으로 쓴 값이다.** `score: 0.8734` · `chunk_index: 1` · `count: 1`은 여전히 미측정값이다. 그런데 이번 세션 `a58ce1f7`은 **같은 질의("교육비는 얼마까지 지원되나요?")로 실제 왕복을 돌려 `score 0.861`을 화면에 띄웠고**, 그 직후 README 106줄을 고치면서도 이 블록은 그대로 뒀다. 값이 없어서 못 고친 게 아니라, 값을 보고도 옮기지 않았다. 청크 1개짜리 문서에서 `chunk_index: 1`은 여전히 불가능한 값이다.
- **스펙 870줄을 Codex 적대적 리뷰 없이 확정했다.** 직전 세 change(`bootstrap-runtime-skeleton` · `add-document-ingestion` · `add-qa-retrieval`)는 전부 확정 전에 Codex 리뷰를 거쳤고, 그때마다 TOCTOU·질의 길이 토크나이저 역산 같은 **설계를 바꾸는** 지적이 나왔다. 이번엔 `codex exec` 호출이 0회다. 그 자리를 사용자의 두 차례 지적(판정 줄 버퍼링 경계, 빈 answer의 의미)이 대신했다 — 리뷰어를 세우지 않으면 사용자가 리뷰어가 된다.
- **MUST-NOT을 프롬프트 3에서야 명시받았다.** 프롬프트 1의 "docker compose up 명령으로 전체 과정이 다 실행될 수 있게"에 이미 "사용자 조작 0"이 들어 있었다. 그런데 프롬프트 3("사용자가 스크립트 실행하면 안 됩니다[MUST-NOT]")과 4("설정 파일 내에서 스크립트를 실행하는 방식은 없나요?")가 **연속으로 같은 지점을 다시 지적**했다. 중간 설계안이 사용자에게 sh 실행을 남겨뒀다는 뜻이다.
- **범위를 넘어갔다.** 프롬프트 6 "스트리밍 이벤트는 구현할 필요가 없습니다"는 교정이다. 세션의 목적은 인증·실행 경로 전환인데 스트리밍까지 건드리려 했다.
- **셸을 섞어 쓴 대가를 네 번 치렀다.** `Unterminated quoted string`, `"(" unexpected`, `sh: 1: -o: not found`, `Python was not found` — 전부 Windows 호스트 · Git Bash · 리눅스 컨테이너 세 셸이 섞인 환경에서 대상 셸을 확정하지 않고 명령을 던진 결과다. 이 환경 구성은 세션 시작 시점에 이미 알고 있었다.

### Try (개선해야 할 것)

- **다음 세션 첫 작업으로 `add-answer-generation` 스펙에 Codex 적대적 리뷰 1회.** 아직 구현 전이므로 지금이 마지막 창이다. `add-qa-retrieval`은 리뷰에서 TOCTOU가 나왔고, 그건 구현 후에 발견했으면 되돌리기 비쌌다. 리뷰 없이 `tasks.md`를 열지 않는다.
- **README `/search` 예시를 실제 응답으로 교체한다 — 이번엔 붙여넣기까지.** `docker compose up` 후 `curl -s -X POST .../search -d '{"query":"교육비는 얼마까지 지원되나요?","top_k":3}'`의 **출력 전체를 그대로** 165~169줄에 넣는다. 209줄의 로그 예시 `top_score: 0.8734`도 같은 실행의 값으로. 값을 눈으로 보고도 안 옮긴 게 이번 문제이므로, "확인한다"가 아니라 "붙여넣는다"가 액션이다.
- **명령을 던지기 전에 대상 셸을 한 단어로 정한다.** Windows 호스트 = PowerShell 도구(리터럴 경로 1개, 파이프라인 체인 없음) / POSIX 스크립트 = Bash 도구 / 컨테이너 안 = `docker compose exec <svc> sh -c '...'`. `curl -o` 같은 옵션을 호스트 셸 인용과 섞지 않는다. 이 세 줄을 명령 작성 직전에 떠올린다.
- **pytest가 실패하면 재실행 전에 실패 이름을 하나씩 읽는다.** `2 failed`면 두 건 모두의 원인을 확인한 뒤 한 번에 고친다. 47초 스위트를 추측으로 다시 돌리지 않는다.
- **요구에 MUST/MUST-NOT이 붙은 문장은 먼저 별도 체크리스트로 옮기고, 설계안 제출 직전에 그 목록과 대조한다.** 세션 `a58ce1f7`의 프롬프트 3·4는 같은 제약을 두 번 말하게 만든 것이다.
- **`retrobot/SKILL.md`에 "통과하는 방법"을 적는다 — 스크립트가 아니라 절차로.** 이번 회차에서 확인된 결론: 이 환경에서 로그 분석에 **실제로 동작하는 도구는 `Grep`(`-o` + 정규식 + `offset`/`head_limit`)과 `Read`(`offset`/`limit`) 둘뿐**이다. 유용했던 패턴을 그대로 남긴다 — 프롬프트 추출은 `"timestamp":"[^"]*","permissionMode":"default","origin":\{"kind":"human"\},"promptSource":"typed"`, 도구 집계는 `"type":"tool_use","id":"[^"]*","name":"[A-Za-z_]*`, 에러는 `.{200}"is_error":true`, 줄 수는 `^` + count. 열두 번 스크립트를 시도해 열두 번 막혔으므로, 열세 번째는 스크립트를 포기하는 쪽이다.
