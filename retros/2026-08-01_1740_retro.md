## KPT 회고

### Keep (좋았던 것)

- **적대적 리뷰를 기본값으로 세팅한 것.** `/codex:review`에 "기본 입장은 반려, 통과시키려면 근거가 필요하다"를 명시해 리뷰어가 작성자 편을 들지 못하게 했다. 자기가 쓴 스펙을 자기가 검토할 때 생기는 확증 편향을 프롬프트 레벨에서 차단한 설계다.
- **모델을 역할별로 나눠 쓴 것.** 리뷰 반영 *계획*은 Fable5, *실제 작업*은 Opus5로 분리했다. 계획과 실행의 성격이 다르다는 판단이 있었고, 결과적으로 두 단계 사이에 검토 지점이 하나 생겼다.
- **리뷰 지적을 그대로 받지 않고 근거까지 되짚은 것.** `index_signature` 건은 "revision이 sha256(bytes) 뿐"이라는 사실 → "재업로드 시 unchanged 단축" → "구/신 벡터 공존" → "캐시 태깅 때문에 stale 답변"까지 인과 사슬을 직접 적어 지시했다. 지적의 수용이 아니라 재구성이었고, 그래서 설계에 정확히 꽂혔다.
- **코드보다 스펙을 먼저 980줄 쓴 것.** 청킹·임베딩·인덱스 무효화는 나중에 바꾸면 캐시 전략까지 연쇄로 흔들리는 영역이다. 구현 착수 전에 design.md에서 결론을 낸 판단이 맞았다.
- **커밋 단위가 깨끗한 것.** 스펙 4개만 담은 `0d27373`과 구현(`chunking.py`)이 분리돼 있어 나중에 "왜 이렇게 설계했나"를 커밋 하나로 되짚을 수 있다.

### Problem (나빴던 것)

- **Retrobot이 매 실행마다 같은 권한 벽에 부딪힌다.** 15:55 실행과 17:40 실행이 *동일한 순서로* 실패했다 — 셸 for 루프(`simple_expansion` 거부) → `python3 -c` 승인 요구 → `/tmp` 스크립트 쓰기 거부 → Grep 폴백. 세 번의 실패가 매번 회고 생성 시간에 그대로 얹힌다.
- **`/codex:review` 백그라운드 실행이 1회 실패했다.** 재실행으로 복구했지만 실패 원인을 확인하지 않고 넘어갔다. 다음에도 같은 확률로 실패한다.
- **`git commit`이 한 번 헛돌았다.** untracked 파일만 있는 상태에서 커밋을 시도해 "Untracked files"만 출력됐다. `git add` 누락.
- **컨텍스트를 한 세션에서 소진해 `/compact`가 필요했다.** 스펙 작성 → 적대적 리뷰 → 리뷰 반영을 한 세션에 몰았고, 압축 이후 초반 논의의 세부가 요약본으로만 남았다.
- **`/opsx:apply` task 1이 커밋 없이 열려 있다.** `src/app/core/chunking.py`가 untracked 상태다. 회고가 커밋 시점 기준으로 생성되므로 이 작업의 과정은 다음 회고까지 기록되지 않는다.

### Try (개선해야 할 것)

- **Retrobot의 로그 분석을 Grep 우선으로 재작성한다.** `retrobot/SKILL.md`의 1~2단계를 "Bash/python 없이 Grep 도구로 `"type":"user"` 패턴을 `-o` 추출"로 바꾸면 실패 3회가 통째로 사라진다. 지금은 매번 셸을 먼저 시도했다가 실패한 뒤에야 폴백한다. → *Problem 1*
- **또는 `.claude/settings.json`에 Retrobot용 권한을 명시한다.** `python3` 실행과 `/tmp` 쓰기를 허용 목록에 넣는 쪽이 근본 해결이다. 어느 쪽이든 하나는 골라야 한다. → *Problem 1*
- **백그라운드 명령 실패 시 출력 파일을 먼저 읽는다.** `/codex:review` 실패 알림에 `<output-file>` 경로가 함께 온다. 재실행 전에 이 파일을 1회 읽는 규칙을 세운다. → *Problem 2*
- **커밋 전 `git status --short`를 습관화한다.** untracked/unstaged를 눈으로 확인한 뒤 `git add`. → *Problem 3*
- **스펙 작성과 구현을 세션 경계로 나눈다.** `/opsx:propose` + 리뷰까지 한 세션, `/opsx:apply`는 새 세션. 압축 없이 각 단계의 논의가 온전히 로그에 남는다. → *Problem 4*
- **`chunking.py` 작업을 오늘 안에 커밋한다.** 미완성 커밋도 괜찮다는 것이 과제 규칙이다(`CLAUDE.md`). → *Problem 5*
