### Keep (좋았던 것)

- **"데이터가 없다"를 가설로 취급하고 증거부터 모았다.** systematic-debugging 스킬을 불러 코드 → 배선 → 서버 직접 조회 순으로 좁혔고, 결과적으로 고칠 게 없다는 결론에 도달했다. 여기서 추측으로 `collection_for()`를 손댔다면 멀쩡한 배선을 망가뜨렸을 것이다. **코드 0줄 수정이 옳은 결론이었던 케이스.**
- **자기 도구 사용 실수를 원인으로 지목했다.** `head -c 3000` 절단 때문에 `d384`를 못 봤다는 걸 GUI 탓으로만 돌리지 않고 먼저 밝혔다. 조사 보고에서 이게 빠지면 다음 사람이 같은 함정에 다시 빠진다.
- **arm64 전용 이미지 위험을 발견하고 `profiles: ["gui"]`로 격리했다.** 평가자 환경(amd64)에서 `docker compose up`이 깨지면 CLAUDE.md의 불합격 기준("명시된 방법으로 실행 불가")에 정면으로 걸린다. 기본 기동 경로를 오염시키지 않은 판단이 과제 조건을 직접 방어했다.
- **사용자 지시를 그대로 따르는 대신 사실을 확인하고 조정했다.** "Volume은 data 폴더 밑에"를 형식적으로 이행해 쓰이지 않을 마운트를 넣는 대신, 붙일 상태가 없다는 걸 확인하고 사유를 compose 주석에 남긴 뒤 보고했다. 근거 있는 불이행.
- **띄웠다고 주장하지 않고 응답으로 증명했다.** GUI 프록시를 통해 `["document_chunks_d384"]`를 실제로 받아 확인한 뒤에 보고했다.

### Problem (나빴던 것)

- **커밋 `8f48961`에 GUI 연결과 무관한 변경이 섞였다.** 세션 시작 시점의 `git diff`에 이미 사용자 수동 편집(named volume → `./data` bind mount 전환)이 있었고, 그 편집이 **설계 근거 주석 9개 블록(약 20줄)을 함께 지웠다** — 헬스체크 순서와 재시작 루프, 자격증명을 `:ro`로 붙이면 안 되는 이유(토큰 8시간 만료), 워커 1개 고정과 `asyncio.Lock`의 관계, registry 볼륨이 따로 필요한 이유, 리눅스 UID 매핑 힌트. 에이전트는 이 삭제를 짚지 않고 그대로 커밋에 실었다. `ARCHITECTURE.md`에 대응 서술이 없다면 설계 기록이 통째로 소실된 것이다.
- **같은 커밋에서 `docker-compose.yml` 끝 개행이 사라졌다** (`\ No newline at end of file`).
- **`volumes:` 최상위 선언(`vector-store`, `registry`)이 삭제됐는데 기존 named volume 데이터의 이관 여부가 확인되지 않았다.** bind mount로 갈아탄 뒤 이전 볼륨에 남은 벡터·레지스트리는 그대로 고아가 된다.
- **GUI 이미지를 고르는 데 세션의 절반을 썼다.** Docker Hub 태그 조회 → GitHub raw 조회 → code search API → 대체 이미지 4종 후보 루프. "Chroma 1.5.9 서버는 자체 UI가 없다"를 첫 단계에서 확정했다면 훨씬 짧았을 탐색이다.
- **`make gui`가 첫 시도에 뜨지 않았고, 원인을 찾기까지 `UI root: 000`을 두 번 받았다.** 이전 세션에서 수동으로 띄운 `nice_jepsen` 컨테이너가 18시간째 포트 3001을 점유하고 있었다. 세션 밖에 방치된 컨테이너가 다음 세션의 디버깅 비용이 됐다.

### Try (개선해야 할 것)

- **커밋 전에 `git diff --stat`이 아니라 삭제 라인(`git diff | grep '^-'`)을 훑는다.** 주석·설계 근거가 지워진 게 있으면 커밋 전에 사용자에게 확인받는다. 특히 **세션 시작 시점에 워킹트리에 이미 편집이 있을 때** — 내가 만들지 않은 변경이라도 내 커밋에 실리면 내 책임이다.
- **지워진 compose 주석 중 살아남아야 할 4건을 `ARCHITECTURE.md`로 옮긴다** — ① 캐시 헬스체크 → API 기동 순서(design 결정 4), ② 자격증명 마운트를 `:ro`로 걸면 안 되는 이유, ③ 워커 1개 고정과 프로세스 내 `asyncio.Lock`(design 결정 8), ④ registry 볼륨 분리 이유. 코드 주석은 이렇게 날아가지만 문서는 남는다.
- **`docker-compose.yml` 끝 개행을 복구하고, 기존 named volume 데이터의 이관/폐기 여부를 명시적으로 결정한다.**
- **세션 중 수동으로 띄운 컨테이너는 `docker ps`로 확인해 정리하거나 compose에 편입한다.** 이번 `nice_jepsen`처럼 이름 없이 남은 컨테이너는 다음 세션에서 원인 불명의 포트 충돌로 돌아온다.
- **섹션 9(불합격 방어)를 다음 세션의 첫 작업으로 고정한다.** [13:02](./2026-08-02_1302_retro.md) · [15:34](./2026-08-02_1534_retro.md)에 이어 이번에도 손대지 않아 **네 번째 미룸**이다. 168시간 창(하드 마감 08-09)에서 남은 여유가 줄고 있고, RAG·캐싱·스트리밍이 아직 통째로 남아 있다.
