### Keep (좋았던 것)

- **축약 요청을 문서 전체 정합성까지 확장해 처리했다.** 평가 비중 표를 지우라는 요청이었지만, `rules`에 남아 있던 `RAG 23%`·`Track C 20점` 같은 참조까지 함께 걷어냈다. 표만 지웠으면 근거가 사라진 숫자가 규칙에 고아로 남았을 것이다.
- **인증 설계를 실측으로 판단했다.** Keychain 항목 존재 여부, 자격증명 JSON 구조, 토큰 만료 시각(access 8시간 / refresh 5.7일)을 직접 확인한 뒤 결정했다. 특히 8시간이라는 수치가 "토큰을 환경변수로 박아두는 방식"을 기각하는 근거가 됐다 — 추측했다면 채택했을 안이다.
- **Codex 지적을 채택/미채택으로 갈라 이유를 남겼다.** 워커 수·스레드풀 오프로드는 관측 가능한 동작이 아니라 구현 방식이므로 spec에 올리지 않았다. 외부 리뷰를 전부 수용하는 것이 항상 옳지는 않다.
- **기각한 대안을 문서에 남겼다.** design 결정 5-1에 `setup-token`·환경변수·Codex 전환을 왜 안 골랐는지 적어둬서, 나중에 같은 논의를 반복하지 않는다.

### Problem (나빴던 것)

- **설치된 도구의 관습을 확인하지 않고 구버전 방식으로 작업했다.** OpenSpec 컨텍스트를 `project.md`에 쓰려다 두 번 중단당했다. 실제 설치본은 1.7.0이고 `openspec/config.yaml`을 읽는다. `openspec doctor`를 한 번만 돌렸어도 "Missing openspec/config.yaml"이 바로 나왔다.
- **Codex 모델 이름을 네 번 추측하며 사용자 시간을 썼다.** 6회 시도 중 5회가 실패였다. `~/.codex/models_cache.json`에 지원 목록(`gpt-5.4`/`gpt-5.4-mini`/`gpt-5.5`)이 처음부터 있었는데, 세 번 실패한 뒤에야 열어봤다. 두 번째 실패 시점에 전환했어야 한다.
- **설계 문서에 확인하지 않은 외부 시스템 동작을 적었다.** "인증 상태를 호스트에서 볼륨으로 주입한다"고 썼지만 macOS는 Keychain을 쓴다. 사용자가 지적해서야 드러났고, 지적이 없었다면 구현 단계에서 터졌을 것이다.
- **검증 불가능한 요구사항을 spec에 넣었다.** design에서 LLM 호출을 전부 비범위로 빼놓고 spec에는 "인증 부재는 사용 시점에 드러난다"를 남겼다. 이 change의 design·tasks만으로는 만족시킬 수 없는 요구사항이다. 자기 문서라 스스로 못 보고 Codex가 잡았다.
- **한국어 규범 문장이 validator를 통과하지 못했다.** "~해야 한다"로 썼지만 도구는 SHALL/MUST 리터럴을 요구한다. 5개 요구사항이 한꺼번에 실패했다.

- **한국어 spec에는 규범 문장 끝에 `(**MUST**)` / `(**SHALL**)`를 붙이는 것을 기본 습관으로 한다.** 작성 후 일괄 수정하지 않는다.
