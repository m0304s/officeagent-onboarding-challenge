### Problem (나빴던 것)

- **자동화 도구를 실행 검증 없이 활성화했다.** 직전 세션에서 훅을 켜고 "회고를 수동 실행"까지 했지만, **훅 경로로는 한 번도 돌려보지 않았다.** 그래서 첫 실제 커밋(`9543347`)에서 바로 터졌다. 수동 실행과 훅 실행은 권한 모델도 타임아웃 주체도 다른데, 전자의 성공을 후자의 성공으로 간주했다.

- **`--allowedTools` 규칙을 문법만 보고 지어냈다.** `'Write(file_path,content)'`는 그럴듯하지만 권한 체크에 매칭되지 않는 형태다. 파라미터 이름을 나열하면 될 것이라고 가정했고, 검증 없이 훅에 박아 커밋했다. 이번 세션의 4번 프롬프트 계열 실수(`12:35 회고`의 Codex 모델명 추측)와 같은 종류다 — **유한한 후보 집합을 문서 확인 없이 추측**했다.

- **경로 인코딩 규칙을 `SKILL.md`와 훅 양쪽에 다르게 적어놨다.** 훅은 `tr '/' '-'`, SKILL.md는 "구분자 `/`가 `-`로"라고 썼는데 실제 규칙은 비영숫자 전체 치환이다. 이 프로젝트 경로에 `_`나 `.`이 없어서 우연히 맞았을 뿐, `claude_code` 같은 상위 디렉토리명 하나만 바뀌어도 로그를 못 찾는다. **우연히 통과한 코드는 검증된 코드가 아니다.**

- **28분간 체크포인트 없이 연속 실행했다.** 12:34 → 13:02 사이 사용자 확인 지점이 하나도 없었다. 실제로 사용자가 13:02에 실수로 중단시켰고("잘못 눌렀습니다"), 그 시점까지의 작업이 어떤 상태였는지 사용자가 판단할 근거가 없었다. 33개 파일·1702줄 규모라면 중간에 한 번은 끊었어야 한다.

### Try (개선해야 할 것)

- **자동화 훅은 활성화 직후 더미 커밋으로 실제 경로를 한 번 태운다.** `git commit --allow-empty -m "test"` 한 번이면 이번 실패를 커밋 전에 잡았다. 훅·크론·CI처럼 "나중에 남이 실행하는" 코드는 작성 시점의 수동 실행이 검증이 아니다.

- **CLI 플래그 값은 `--help` 또는 공식 문서에서 확인한 뒤 쓴다.** `--allowedTools`의 규칙 문법처럼 형태가 정해진 값은 추측 대상이 아니다. 이번 세션의 진단 과정에서 실제로 `claude --help | grep -i allowedtools`를 돌렸는데, **그 명령을 훅을 쓸 때 먼저 돌렸어야 했다.**

- **같은 규칙을 두 곳에 적을 때는 한 곳을 원본으로 정하고 나머지는 그걸 참조하게 한다.** 경로 인코딩처럼 코드(훅)와 문서(SKILL.md) 양쪽에 있는 규칙은 반드시 어긋난다. 최소한 수정할 때 짝을 함께 훑는 습관을 들인다 — 이번엔 다행히 함께 고쳤다.

- **"우연히 동작하는 코드"를 발견하면 반례를 만들어 확인한다.** `tr '/' '-'`가 이 경로에서 맞았다는 사실은 규칙이 옳다는 증거가 아니다. `_`가 포함된 경로 하나로 대조해봤어야 하고, 실제로 이번엔 `sed`와 `tr` 결과를 나란히 출력해 확인했다. 이 방식을 기본값으로 삼는다.

- **30분 이상 걸릴 작업은 시작 전에 중간 확인 지점을 선언한다.** "뼈대 → 테스트 하네스 → 라우트 → 문서" 같은 단위로 끊고, 각 단위 끝에서 상태를 한 줄로 보고한다. 사용자가 중단 여부를 판단할 수 있어야 한다.

- **린트는 파일 단위로 쓰는 즉시 돌린다.** 33개를 다 쓴 뒤 일괄 검사하면 같은 위반이 여러 파일에 복제된 뒤에 발견된다. 첫 파일에서 잡았다면 나머지 32개는 애초에 안 어겼다.
