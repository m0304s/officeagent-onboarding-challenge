## Purpose

서비스가 어떤 조건에서 기동하고, 자신과 백엔드 의존성의 상태를 외부에 어떻게 보고하는지를 규정한다. 운영자와 평가자가 배포된 인스턴스를 실행해 볼 때 "떠 있는가, 무엇이 불능인가"를 한 번의 요청으로 판단할 수 있게 하는 것이 목적이다.

## Requirements

### Requirement: 서비스는 단일 명령으로 기동된다

깨끗한 체크아웃 상태에서 문서에 명시된 **하나의 명령**으로 서비스와 외부 백엔드 의존성이 함께 기동되어야 한다 (**MUST**). 프로세스에 내장되는 의존성은 별도 서비스로 기동되지 않으며, 마운트된 저장 경로가 준비되는 것으로 충족된다. 사전 수작업 설정(수동 마이그레이션, 자격증명 발급, 외부 계정 연결)을 요구해서는 안 된다 (**MUST NOT**).

#### Scenario: 깨끗한 체크아웃에서 기동

- **WHEN** 리포지토리를 새로 받은 환경에서 문서에 명시된 기동 명령을 1회 실행한다
- **THEN** 서비스와 외부 백엔드 의존성이 함께 기동되고, 추가 수작업 없이 헬스 엔드포인트가 응답한다

#### Scenario: 자동화 테스트 실행

- **WHEN** 문서에 명시된 테스트 명령을 1회 실행한다
- **THEN** 전체 테스트 스위트가 실행되고, 외부 계정이나 자격증명 없이 통과한다

#### Scenario: 설정을 전혀 제공하지 않음

- **WHEN** 설정 항목을 하나도 제공하지 않은 상태로 서비스를 기동한다
- **THEN** 문서화된 기본값으로 기동에 성공한다

#### Scenario: 필수 설정 값이 무효함

- **WHEN** 필수 설정 항목에 형식이 맞지 않는 값을 제공한 상태로 기동을 시도한다
- **THEN** 기동이 실패하고, 어느 설정 항목이 왜 무효한지 식별할 수 있는 메시지가 남으며, 잘못된 설정으로 조용히 기동되지 않는다

### Requirement: 서비스는 외부 LLM 제공자 인증 없이 기동한다

LLM 제공자 인증은 답변 생성 시점에만 필요하다. 인증 정보의 부재나 손상이 서비스 기동 또는 헬스 보고를 막아서는 안 된다 (**MUST NOT**). 기동 경로에서 LLM 제공자를 호출해서는 안 된다 (**MUST NOT**).

> 인증이 없을 때 LLM 기능 요청이 어떤 오류를 반환하는지는 이 capability의 범위가 아니다. 해당 기능을 도입하는 change에서 규정한다.

#### Scenario: 인증 정보 없이 기동

- **WHEN** LLM 제공자 인증 정보가 없는 환경에서 서비스를 기동한다
- **THEN** 기동에 성공하고, 헬스 엔드포인트가 정상 상태를 반환한다

#### Scenario: 자격증명이 손상되었거나 읽을 수 없음

- **WHEN** LLM 제공자 자격증명이 손상되었거나 판독 불가능한 상태로 존재하는 환경에서 서비스를 기동한다
- **THEN** 기동에 성공하고, 헬스 엔드포인트가 정상 상태를 반환하며, 헬스 응답이 LLM 제공자 상태를 근거로 불가용을 보고하지 않는다

### Requirement: 헬스 엔드포인트는 서비스와 의존성 상태를 함께 보고한다

헬스 엔드포인트는 서비스 자신의 응답 가능 여부와, 각 백엔드 의존성(벡터 스토어, 캐시 저장소)의 도달 가능 여부를 개별적으로 보고해야 한다 (**SHALL**). 의존성이 몇 개가 불능이든 엔드포인트 자체는 응답해야 하며 (**MUST**), 어느 의존성이 문제인지 식별 가능해야 한다 (**SHALL**).

응답 본문은 전체 상태와 의존성별 상태를 모두 포함해야 하고 (**SHALL**), 의존성 목록은 정상·비정상 여부와 무관하게 항상 동일한 집합이어야 한다 (**MUST**). 실패 사유 요약에 내부 구현 세부 정보(스택 트레이스, 접속 문자열, 자격증명)가 포함되어서는 안 된다 (**MUST NOT**).

#### Scenario: 모든 의존성 정상

- **WHEN** 벡터 스토어와 캐시 저장소가 모두 도달 가능한 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 성공 상태 코드와 함께 전체 상태가 정상임을 나타내는 본문이 반환되고, 각 의존성이 개별적으로 정상으로 표시된다

#### Scenario: 캐시 저장소 불능

- **WHEN** 캐시 저장소가 도달 불가능한 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 서비스 불가용을 나타내는 상태 코드가 반환되고, 본문에서 **캐시 저장소만** 비정상으로 표시되며 벡터 스토어는 정상으로 표시된다

#### Scenario: 벡터 스토어 불능

- **WHEN** 벡터 스토어가 도달 불가능한 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 서비스 불가용을 나타내는 상태 코드가 반환되고, 본문에서 **벡터 스토어만** 비정상으로 표시된다

#### Scenario: 벡터 스토어 저장 경로에 쓸 수 없음

- **WHEN** 벡터 스토어의 저장 경로가 마운트되지 않았거나 쓰기 권한이 없는 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 벡터 스토어가 비정상으로 표시된다. 클라이언트 객체가 생성되었다는 사실만으로 정상으로 표시되지 않는다

#### Scenario: 두 의존성이 동시에 불능

- **WHEN** 벡터 스토어와 캐시 저장소가 모두 도달 불가능한 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 엔드포인트가 응답하고, 본문에서 **두 의존성 모두** 비정상으로 표시된다

#### Scenario: 점검 자체가 예상치 못한 예외로 실패

- **WHEN** 의존성 점검이 도달 불가가 아닌 예상하지 못한 예외로 실패한다
- **THEN** 엔드포인트가 응답하고, 해당 의존성이 비정상으로 표시되며, 예외의 내부 세부 정보가 응답 본문에 노출되지 않는다

### Requirement: 헬스 점검은 유한 시간 안에 응답한다

의존성 점검에는 **의존성별 상한 시간과 전체 상한 시간이 모두** 있어야 한다 (**SHALL**). 응답하지 않는 의존성 때문에 헬스 요청이 무한정 매달려서는 안 된다 (**MUST NOT**). 한 의존성이 상한에 걸려도 나머지 의존성의 점검 결과는 보고되어야 한다 (**SHALL**).

#### Scenario: 의존성이 응답하지 않음

- **WHEN** 백엔드 의존성이 연결은 되지만 응답하지 않는 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 정해진 상한 시간 안에 응답이 반환되고, 해당 의존성이 비정상으로 표시된다

#### Scenario: 한 의존성만 무응답이고 나머지는 정상

- **WHEN** 한 의존성은 응답하지 않고 다른 의존성은 정상인 상태에서 헬스 엔드포인트를 호출한다
- **THEN** 상한 시간 안에 응답이 반환되고, 무응답 의존성은 비정상으로, 정상 의존성은 정상으로 각각 표시된다

### Requirement: 오류 응답은 일관된 형식을 따른다

모든 오류 응답은 동일한 본문 구조를 사용해야 한다 (**SHALL**). 내부 예외의 세부 정보(스택 트레이스, 내부 식별자, 의존성 접속 문자열)가 응답 본문에 노출되어서는 안 된다 (**MUST NOT**).

헬스 엔드포인트의 응답은 이 요구사항의 적용 대상이 아니다. 헬스는 오류를 알리는 것이 아니라 상태를 보고하는 엔드포인트이므로, 불가용을 나타내는 상태 코드를 반환할 때에도 공통 오류 형식이 아니라 상태 보고 본문을 사용해야 한다 (**SHALL**).

#### Scenario: 존재하지 않는 경로

- **WHEN** 정의되지 않은 경로로 요청한다
- **THEN** 없음을 나타내는 상태 코드와 함께 공통 오류 형식의 본문이 반환된다

#### Scenario: 허용되지 않은 메서드

- **WHEN** 정의된 경로에 그 경로가 지원하지 않는 메서드로 요청한다
- **THEN** 메서드 불허를 나타내는 상태 코드와 함께 공통 오류 형식의 본문이 반환된다

#### Scenario: 요청 검증 실패

- **WHEN** 정의된 경로에 형식이 맞지 않는 요청을 보낸다
- **THEN** 검증 실패를 나타내는 상태 코드와 함께 공통 오류 형식의 본문이 반환되고, 어떤 입력이 문제인지 식별할 수 있다

#### Scenario: 처리되지 않은 내부 오류

- **WHEN** 요청 처리 중 예상하지 못한 내부 오류가 발생한다
- **THEN** 내부 오류를 나타내는 상태 코드와 공통 오류 형식의 본문이 반환되고, 본문에 내부 구현 세부 정보가 포함되지 않으며, 원인을 추적할 수 있는 정보는 서버 로그에 남는다

#### Scenario: 헬스 불가용 응답은 오류 형식을 쓰지 않는다

- **WHEN** 의존성 불능으로 헬스 엔드포인트가 불가용 상태 코드를 반환한다
- **THEN** 본문은 공통 오류 형식이 아니라 의존성별 상태를 담은 상태 보고 형식이다
