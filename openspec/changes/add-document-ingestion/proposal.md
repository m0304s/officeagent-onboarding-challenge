## Why

`bootstrap-runtime-skeleton`이 실행되는 빈 서버를 만들었다. 도메인은 아직 하나도 없다. 지금 필요한 것은 **답변의 근거가 되는 데이터가 저장소에 들어가는 경로**다.

ingestion을 먼저 하는 이유는 순서 때문만이 아니다. 이후 세 change가 전부 ingestion이 **무엇을 어떤 모양으로 써 두었는지**에 종속된다.

- 청크에 위치 정보가 남지 않으면 retrieval이 찾아와도 **출처를 만들 수 없다**.
- 재업로드가 "덧붙이기"인지 "교체"인지 정하지 않으면, 캐시 무효화 change가 **무엇을 무효화 신호로 삼을지 정할 근거가 없다**. 이 결정을 뒤로 미루면 캐싱 설계 도중에 ingestion을 다시 뜯게 된다.
- 저장된 벡터가 **어떤 색인 구성으로 만들어졌는지**를 남기지 않으면, 모델이나 청킹을 바꿔도 문서 내용은 그대로라 변경 신호가 발생하지 않는다. 구 구성 벡터가 인덱스에 남은 채 캐시는 낡은 답변을 계속 내보낸다. 그래서 이 change가 `index_signature`까지 확정한다.

그래서 이 change는 저장 결과의 모양과 재업로드 의미론까지 확정한다.

**PRD 대응**: §1 문서 수집(Ingestion)을 직접 충족하고, §5 자동화 테스트 3경로 중 **Ingestion 경로**를 덮는다. §2 Query & Answer · §3 캐싱 · §4 프롬프트는 다루지 않는다.

## What Changes

- **`POST /documents`** — multipart 업로드. 텍스트 추출 → 청킹 → 임베딩 → 벡터 저장까지 한 요청 안에서 끝내고, 저장 결과(문서 식별자·리비전·청크 수)를 응답한다.
- **포맷 두 가지** — TXT/MD와 PDF. 포맷별 파서를 프로토콜 뒤에 두어 셋째 포맷이 상위 계층을 건드리지 않고 붙게 한다.
- **청킹과 임베딩** — 문서를 구조 경계 기준으로 청크로 나누고 로컬 임베딩 모델로 벡터화해 벡터 스토어에 넣는다. 각 청크는 **원문 위치**(PDF는 페이지, 텍스트는 문자 오프셋)를 함께 저장한다. 출처 표기의 전제다. 분할 전략은 설정 선택지로 두되 **이번에 구현하는 것은 재귀 분할(`recursive`) 하나**이며, 부모-자식 같은 다음 후보는 검색 경로가 생긴 뒤 같은 자리에 붙인다.
- **재업로드 의미론 확정** — 문서 식별자는 파일명에서 결정론적으로 유도하고, 리비전은 내용 해시로 정한다. 같은 내용이면 재색인하지 않고, 내용이 바뀌면 **교체**한다(덧붙이지 않는다). 리비전 교체는 새 청크를 먼저 쓰고 이전 리비전을 지우는 순서이며, 도중에 실패하면 같은 요청 안에서 새 청크를 되돌려 이전 리비전만 남긴다. 같은 문서에 대한 동시 요청은 문서 단위로 직렬화해 두 리비전이 뒤섞이지 않게 한다.
- **색인 서명(`index_signature`)** — 임베딩 모델 정체성(모델·차원·정규화·역할 접두사)과 청킹 구성(전략·버전·크기·겹침)에서 서명을 유도해 문서 레코드와 모든 청크에 남긴다. "내용이 같으면 건너뛴다"는 단축은 `revision`과 서명이 **둘 다** 같을 때만 걸리므로, 구성을 바꾼 뒤 같은 파일을 올리면 재색인된다(`status: "reindexed"`). 재업로드가 없는 경우까지 덮기 위해 **기동 시** 서명이 어긋난 문서의 청크를 제거하고 `index_status: "stale"`로 드러낸다. 새로 생기는 설정은 `chunk_strategy` 하나뿐이다.
- **문서 레지스트리** — 문서별 현재 리비전·색인 서명·색인 상태·파일명·포맷·청크 수·수집 시각. 벡터 인덱스와 분리한다. "지금 유효한 리비전이 무엇인가"에 단일 답이 있어야 교체가 원자적이 된다.
- **`GET /documents` · `GET /documents/{id}`** — 수집 결과 조회. 실패한 업로드가 아무것도 남기지 않았음을 확인할 수 있는 관측 지점이기도 하다.
- **`DELETE /documents/{id}`** — 문서와 그 청크를 지운다. *범위를 넘는 것처럼 보이므로 이유를 밝힌다*: 교체 구현이 이미 "문서 단위 청크 삭제"를 포함하므로 추가 비용이 거의 없고, 캐시 무효화 change가 요구하는 "문서 변경(추가·삭제·재업로드)" 중 삭제 경로가 여기 없으면 그 change가 ingestion을 다시 열어야 한다.
- **오류 경로 명시** — 미지원 포맷 / 내용 없는 문서 / 텍스트 레이어 없는 PDF / 상한 초과 크기. 넷 다 **아무것도 저장하지 않고** 서로 다른 오류 코드로 구분된다. 스캔본 PDF를 "빈 문서"와 같은 코드로 뭉개면 클라이언트가 OCR이 필요한 상황인지 판단할 수 없다. 저장소 실패는 `503 storage_unavailable`로 따로 구분된다.
- **블로킹 작업 오프로드와 배치 처리** — PDF 파싱과 임베딩 인코딩은 CPU 바운드다. 스레드풀로 내보내고, 임베딩·저장은 배치 단위로 끊어 배치 사이에 이벤트 루프에 양보한다. 메모리가 문서 크기가 아니라 배치 크기에 비례하고, 수집이 진행되는 동안에도 다른 요청이 응답한다.
- **문서 갱신** — `ARCHITECTURE.md`(청킹 전략, 파서·임베딩·벡터 스토어 어댑터, 레지스트리 도입 이유), `README.md`(엔드포인트, 새 설정 항목).

**명시적 비범위** — 벡터 **검색** 질의(retrieval change), LLM 호출·스트리밍·프롬프트(QA change), 캐시 키 구성과 무효화 실행(캐싱 change), OCR, 비동기 작업 큐, 인증·인가. 이 change는 "검색 가능한 상태로 저장된다"까지만 책임진다.

## Capabilities

### New Capabilities

- `document-ingestion`: 문서 업로드부터 검색 가능한 청크 저장까지의 계약. 어떤 포맷을 받는지, 저장 결과가 무엇을 보장하는지(위치 정보, 청크 수, 색인 서명), 같은 문서를 다시 올리면 무슨 일이 일어나는지, 색인 구성이 바뀌면 저장된 청크가 어떻게 되는지, 수집이 거부되는 조건과 그때 저장소에 무엇이 남는지를 규정한다.

### Modified Capabilities

없음. `service-health`의 의존성 집합(벡터 스토어, 캐시 저장소)과 오류 응답 형식은 그대로다. 이 change는 오류 코드 목록에 항목을 **추가**할 뿐 형식을 바꾸지 않는다.

## Impact

**코드** — 신규가 대부분이다.

| 계층 | 추가 |
|------|------|
| `api/` | `routes/documents.py`, 업로드 검증, 새 오류 코드 → HTTP 매핑 |
| `services/` | `ingestion.py` — 파싱·청킹·임베딩·저장 오케스트레이션, 리비전 교체 순서 |
| `core/` | 청킹 전략 레지스트리와 `recursive` 구현, 문서·청크 값 객체, 문서 식별자·리비전·색인 서명 유도 규칙, 새 도메인 예외 |
| `adapters/` | `DocumentParser` 프로토콜 + 텍스트/PDF 구현, `Embedder` 프로토콜 + 구현, `VectorStore` 프로토콜(쓰기·삭제 측면) + 구현, 문서 레지스트리 |

`adapters/protocols.py`가 `HealthProbe` 하나만 정의해 둔 것은 "소비자가 생길 때 정의한다"는 규약 때문이었다. 이 change가 그 소비자다.

**의존성 추가** — PDF 파서, 로컬 임베딩 모델 런타임. 임베딩 모델 가중치는 이미지 빌드 단계에서 받아 첫 요청 지연과 런타임 네트워크 의존을 없앤다. 문서 레지스트리는 표준 라이브러리로 해결해 컨테이너를 늘리지 않는다.

**인프라** — 새 서비스는 없다. 레지스트리는 벡터 스토어와 같은 볼륨에 둔다. 이미지 크기는 PDF 파서와 임베딩 모델만큼 늘어난다.

**설정** — 임베딩 모델 이름, **분할 전략**(기본 `recursive`), 청크 크기·겹침, 임베딩 배치 크기, 업로드 크기 상한, 레지스트리 경로, 수집 동시성 상한. 전부 기본값이 있어야 한다(설정 없이 기동된다는 기존 요구사항 유지). `index_signature`는 이 값들과 임베딩 어댑터가 아는 사실에서 **유도**되며 설정 항목이 아니다 — 손으로 적을 수 있게 하면 실제 구성과 어긋날 수 있어 서명의 의미가 사라진다.

**테스트** — PRD §5의 Ingestion 경로가 여기서 채워진다. 임베딩은 로컬 모델이라 목이 아니라 실물로 돌리고, LLM은 이 change에서 호출하지 않으므로 스위트는 여전히 구독 없이 통과한다.

**이후 change에 남기는 계약** — 청크 스키마(문서 식별자, 리비전, 색인 서명, 위치 정보), `VectorStore`·`Embedder` 프로토콜, `core/chunking.py`의 전략 레지스트리, 그리고 **`(document_id, revision, index_signature)`가 저장된 벡터의 완전한 정체성**이라는 사실. 캐싱 change는 이 셋을 무효화 키로 쓴다 — 문서가 바뀌어도, 색인 방식이 바뀌어도 같은 통로로 무효화된다.
