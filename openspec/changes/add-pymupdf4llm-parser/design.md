## Context

동기와 범위는 `proposal.md` 에 있다. 여기서는 지금 코드가 이 변경에 대해 이미 정해 놓은 제약만 적는다.

- **파서는 프로토콜 뒤에 있다.** `DocumentParser` 는 `formats: frozenset[DocumentFormat]` 와 `parse(bytes) -> ExtractedDocument` 둘뿐이고, 동기다 — 호출부가 스레드풀 오프로드를 의식하게 만들려는 의도적 선택이다. 두 번째 PDF 구현이 들어와도 상위 계층(서비스·라우터)이 바뀌지 않는다.
- **`ParserRegistry` 는 한 포맷에 파서 둘을 등록하면 기동에서 터진다.** 조용히 덮어쓰면 어느 파서가 쓰이는지가 등록 순서에 달리기 때문이다. 그래서 두 구현의 공존은 "둘 다 등록"이 아니라 **"둘 중 하나를 고른 뒤 등록"** 이어야 한다.
- **`ExtractedDocument` 는 `(segments, page_count)` 다.** 세그먼트는 `(text, page)` 이고 쪽 경계가 여기서 유지되어야 청커가 "청크는 페이지를 넘지 않는다"를 지킬 수 있다.
- **`index_signature` 는 `main.py` 에서 한 번만 유도된다.** 두 서비스가 각자 유도하면 한쪽만 고쳐진 순간 방금 올린 문서가 조용히 검색되지 않는다.
- **`core/` 는 `pymupdf` 를 import 할 수 없다** — `src/app/core/.ruff.toml` 의 `banned-api` 가 막는다. PDF 파싱은 `adapters/parsers` 의 관심사다.
- **테스트용 PDF 는 픽스처가 만든다** (`tests/pdf_fixtures.py`, PyMuPDF 로 생성). 표·큰 글씨 제목이 있는 PDF 도 여기서 만들어야 한다.

## Goals / Non-Goals

**Goals:**

- 기존 `adapters/parsers/pdf.py` 를 **한 줄도 고치지 않고** 두 번째 PDF 구현을 추가한다. 되돌리기가 "코드를 되살리는 일"이 아니라 "설정값을 바꾸는 일"이 되게 한다.
- 선택 축을 **결과의 모양**(`markdown` / `plain`)으로 이름 붙여, 스펙과 설정이 라이브러리 이름에 매이지 않게 한다.
- 추출 방식 변경이 기존 `stale` → 재업로드 경로를 그대로 타게 한다. 새 무효화 메커니즘을 만들지 않는다.
- 두 구현이 오류 코드·쪽 번호에서 갈라지지 않게 **계약 테스트로 묶는다.**

**Non-Goals:**

- 청킹을 마크다운 인지형으로 바꾸지 않는다. 헤딩을 최우선 분할 경계로 삼는 것도, **부모-자식 계층형 인덱싱**도 별도 change 다(`CHUNK_STRATEGY_VERSION` 을 올리는 변경이라 서명 축이 겹친다). 검토 결과는 아래 「계층형 인덱싱 검토」에 남긴다.
- 표를 구조화 데이터로 파싱해 따로 저장하지 않는다. 이번에 표는 **마크다운 텍스트**일 뿐이다.
- 이미지 추출·저장·OCR 은 하지 않는다.
- `.txt` · `.md` 파서는 건드리지 않는다.

## Decisions

### 1. 두 구현은 파일 둘, 선택은 배선 한 곳

`adapters/parsers/pdf.py`(기존, 평문)를 그대로 두고 `adapters/parsers/pdf_markdown.py`(신규, 마크다운)를 추가한다. 어느 쪽을 쓸지는 설정이 정하고, 그 선택 결과를 `default_parsers(choice)` 가 받는다.

```
config.Settings.pdf_extraction ─→ select_pdf_extraction(mode) ─→ PdfExtractionChoice
                                                                   ├─ .parser ──────────→ default_parsers(choice) → ParserRegistry
                                                                   └─ .signature_material → derive_index_signature(…)
```

**대안 1 — 한 파서 안에서 분기.** `PdfParser.parse()` 안에서 방식에 따라 다른 라이브러리를 부른다. 파일은 하나로 남지만 두 라이브러리의 import·예외 처리·후처리가 한 클래스에 섞이고, "교체 지점은 파일 하나"라는 기존 성질이 "교체 지점은 함수 안 분기"로 나빠진다. 기존 파일을 고치지 않는다는 요구와도 어긋난다.

**대안 2 — 레지스트리가 우선순위로 덮어쓰게 한다.** 중복 등록 금지를 풀고 나중 것이 이긴다. 지금 그 금지가 잡고 있는 실패(배선 실수가 기동이 아니라 업로드 시점에 드러나는 것)를 다시 연다. 채택하지 않는다.

### 2. 선택 축의 이름은 구현이 아니라 결과의 모양

설정값은 `pymupdf` / `pymupdf4llm` 이 아니라 `plain` / `markdown` 이다.

- 스펙 규칙(관측 가능한 동작만, 라이브러리 이름은 design 으로)을 설정 이름이 어기지 않는다.
- 나중에 같은 마크다운 결과를 다른 라이브러리로 내도 **설정값과 스펙이 그대로**다. 라이브러리 이름을 설정에 박으면 교체가 곧 설정 호환성 파괴다.
- 값의 이름이 사용자가 실제로 고르는 것(구조를 보존할 것인가)을 말한다.

열거형 `PdfExtraction` 은 `adapters/parsers/selection.py` 에 둔다. 방식 → 구현 배선이 이 축의 유일한 진실이고, `config.py` 가 이미 `adapters` 에서 `RETRIEVER_NAMES` 를 import 하는 선례가 있다. 알 수 없는 값은 pydantic 열거형 검증이 기동에서 막는다 — `ChunkStrategy` 와 같은 처리다.

**선택은 한 번만 일어나고, 파서와 서명 재료가 그 하나에서 함께 나온다.**

```python
@dataclass(frozen=True)
class PdfExtractionChoice:
    mode: PdfExtraction
    parser: DocumentParser

    @property
    def signature_material(self) -> str:
        return f"{self.mode.value}:v{PDF_EXTRACTION_VERSION}"

def select_pdf_extraction(mode: PdfExtraction) -> PdfExtractionChoice: ...
```

```python
choice = select_pdf_extraction(settings.pdf_extraction)
index_signature = derive_index_signature(..., pdf_extraction_signature=choice.signature_material)
ParserRegistry(default_parsers(choice))
```

설정값을 서명과 배선에 각각 넘기면 **둘이 어긋나도 아무 데서도 오류가 나지 않는다** — 마크다운으로 뽑은 청크가 `plain` 서명으로 저장되고, 그 문서는 이후 영원히 자기 서명과 다른 내용을 들고 있게 된다. 실제로 터지는 자리는 테스트 하네스다. 한쪽만 지정하고 다른 쪽은 기본값을 쓰는 것이 가장 쓰기 쉬운 코드이기 때문이다. 객체 하나에서 둘 다 꺼내면 어긋나려면 `select_pdf_extraction` 을 두 번 불러야 하고, 그건 한 함수 안에서 눈에 보인다.

같은 이유로 `default_parsers` 에 **기본 인자를 두지 않는다.** 기본값이 있는 한 "서명은 지정했는데 파서는 기본값"이 계속 가능하다.

이것은 `main.py` 가 서명을 한 곳에서만 유도하는 기존 규칙("두 서비스가 각자 유도하면 한쪽만 고쳐진 순간 방금 올린 문서가 오류 없이 검색되지 않는다")의 같은 형태다.

### 3. 추출은 `to_markdown()` 하나로 확정한다 — 문서는 우리가 연다

**버전을 `pymupdf4llm==1.28.0` 으로 고정한다.** 추출 결과가 저장물이고 저장물이 서명 축이므로, 버전이 흔들리면 같은 설정에서 같은 PDF 가 다른 청크가 된다 — 고정은 취향이 아니라 이 설계의 전제다. 아래 호출에 쓰는 인자와 반환 조각의 키는 **그 버전의 계약**이며, 고정 덕분에 "옵션이 있는지 없는지"를 런타임에 물을 필요가 없다. 이 버전은 `pymupdf==1.28.0` 을 정확히 요구하므로 `pymupdf` 도 같은 값으로 고정한다(기존 `>=1.24` 를 대체).

**핀을 올리면 `PDF_EXTRACTION_VERSION` 도 함께 올린다.** 버전이 바뀌면 추출 결과가 달라질 수 있고, 서명이 그것을 모르면 옛 청크가 새 청크와 한 인덱스에 남는다. 설치된 버전을 읽어 서명 재료에 자동으로 넣는 방법도 있으나, 그러면 서명이 소스가 아니라 **환경**의 함수가 되어 같은 커밋이 환경마다 다른 서명을 갖는다. 핀이 있는 한 두 값은 같은 커밋에서 함께 움직이므로, 손으로 올리되 **그 규칙을 여기와 `tasks.md` 양쪽에 적어 둔다.**

**평문 추출(`page.get_text()`)로 되돌아가는 경로는 `plain` 파서 안에만 있다.** `markdown` 파서는 어떤 경우에도 `to_markdown()` 의 결과만 내놓는다 — 표 탐지가 실패했다고 평문으로 물러서는 폴백을 두지 않는다. 두면 같은 설정에서 문서마다 다른 모양이 나오고, 추출 방식이 서명 축이라는 결정(결정 5)이 무의미해진다.

```
pymupdf.open(stream=data, filetype="pdf")   ← 우리가 연다
  ├─ needs_pass 판정            → DocumentParseError("암호로 보호된 PDF …")
  ├─ page_count 확보
  └─ pymupdf4llm.to_markdown(
         document,
         page_chunks=True,        # 쪽마다 조각 하나 → TextSegment(page=n)
         page_separators=False,   # 쪽 구분선을 본문에 넣지 않는다
         write_images=False,      # 파일시스템에 쓰지 않는다
         # table_strategy 는 기본값(격자선)을 쓴다 — 스펙이 약속한 범위와 같다
     )
```

바이트를 `to_markdown` 에 통째로 넘기지 않고 `Document` 를 넘긴다.

- **암호 PDF·손상 PDF 의 판정 원천이 기존과 같아진다.** 예외를 던지는 코드가 양쪽 모두 `pymupdf.open` 이므로, 오류 코드가 방식에 따라 갈라질 여지가 구조적으로 없다.
- `page_count` 를 `to_markdown` 결과의 길이로 세지 않아도 된다. 스캔본 판정(`no_extractable_text`)이 "쪽은 있는데 텍스트가 없다"는 비교라서, 쪽 수의 출처가 텍스트 추출과 독립이어야 한다.
- `page_chunks=True` 의 조각 하나가 `TextSegment(page=n)` 하나가 된다 — 합쳐 놓고 나중에 쪼개면 페이지 정보를 복원할 수 없다.

**쪽 번호는 조각의 `metadata["page_number"]` 에서 읽고, 없으면 파싱 실패로 던진다.** 돌아온 목록의 순번으로 세면 변환기가 어떤 이유로든 쪽을 건너뛰는 순간 그 뒤 모든 출처가 한 쪽씩 밀리는데, **오류는 나지 않는다** — 답변은 계속 나오고 인용만 틀린다. 조용한 실패는 던지는 실패로 바꾼다.

조각에는 마크다운 본문(`text`) 외에 `toc_items`·`tables`·`images`·`graphics` 가 함께 온다. **이번 change 는 `text` 만 쓴다** — 나머지를 쓰려면 `ExtractedDocument` 가 그것들을 담을 자리를 가져야 하고, 그 자리는 쓰는 쪽(계층형 인덱싱)이 정해져야 모양이 맞는다(아래 「계층형 인덱싱 검토」).

헤딩 판정은 기본값(`hdr_info=None`, 폰트 크기 분포 스캔)을 쓴다. 목차(outline)가 있는 PDF 에서 더 정확한 `TocHeaders` 대안이 있으나, 목차 없는 PDF 가 흔한 평가 시나리오에서 기본 경로를 갈아 끼울 근거가 없다.

라이브러리 import 는 기존 파일과 같이 **함수 안**에 둔다. C 확장 import 비용을 PDF 를 한 번도 올리지 않는 배포가 부담하지 않게 하려는 기존 근거가 그대로 적용된다.

### 4. 구조 기호만 남은 쪽은 텍스트가 없는 쪽이다

기존 평문 파서는 `text.strip()` 이 비면 그 쪽을 버린다. 같은 판정을 마크다운 결과에 그대로 쓰면 **내용이 없는 쪽이 표기만으로 살아남는다** — 셀이 빈 격자만 있는 쪽은 `| |` 행으로, 구분선이 그어진 쪽은 하이픈 줄로 남는다. 그 쪽이 통과하면 스캔본 PDF 가 `no_extractable_text` 대신 기호뿐인 청크로 저장된다.

그래서 마크다운 파서는 쪽을 버릴지 판정할 때 **구조 기호(`#`, `|`, `-`, `*`, `>`, 공백)만 남은 쪽을 빈 쪽으로 본다.** 판정에만 쓰고, 저장되는 본문은 변환 결과 그대로다 — 기호를 지우면 구조를 보존하려고 만든 표기를 스스로 지우는 셈이 된다.

쪽 구분선은 `page_separators=False` 로도 막는다(결정 3). 그래도 이 판정을 함께 두는 것은 **구분선이 빈 쪽의 유일한 실패 모양이 아니기** 때문이다 — 셀이 빈 격자만 있는 쪽은 옵션과 무관하게 `| |` 행으로 남는다.

옵션 쪽은 고정된 버전의 계약이라 있고 없고를 의심하지 않는다. 다만 **모르는 키워드 인자는 조용히 무시되지 않고 `TypeError` 로 죽는다** — 핀을 올릴 때 이 호출부가 그 버전에서도 유효한지 확인하는 것이 `PDF_EXTRACTION_VERSION` 을 올리는 것과 함께 따라온다.

### 5. 추출 구성은 `index_signature` 의 재료다 — 전 포맷 공통으로

`derive_index_signature` 에 재료 **한 칸**을 더한다: `pdf_extraction_signature`, 값은 `"markdown:v1"` 꼴이다.

- **이름과 버전을 두 파라미터로 나누지 않는 것**은 `tokenizer_signature=DEFAULT_TOKENIZER.signature_material` 선례를 그대로 따르는 것이다. 재료를 만드는 책임이 재료를 아는 모듈에 남고, `core/` 는 그것이 무엇으로 이루어졌는지 몰라도 된다.
- **버전을 재료에 넣는 이유**는 `CHUNK_STRATEGY_VERSION` 과 같다. 방식 이름은 그대로인데 산출물이 달라지는 변경(라이브러리 업그레이드, 후처리 수정)을 잡을 다른 수단이 없다. 소스 해시로 자동 유도하면 주석 한 줄 수정에도 전면 재색인이 돈다.
- **재료 목록은 계약이다.** `tests/test_documents.py` 가 `parameters == set(BASE_SIGNATURE_MATERIALS)` 를 단언하므로 재료를 늘리면 그 테스트가 반드시 깨진다. 깨지는 것이 정상이고, 갱신이 곧 "재료를 늘렸다"는 선언이다.
- **포맷별 서명으로 쪼개지 않는다.** PDF 추출 방식은 PDF 문서에만 영향을 주므로 정밀하게 하려면 서명을 포맷마다 두어야 한다. 그러면 "이 문서가 현재 구성으로 색인되었는가"의 답이 포맷마다 달라지고, 기동 정리·`stale` 판정·캐시 무효화가 전부 포맷을 알아야 한다. 어휘 토크나이저 구성을 같은 서명에 넣을 때 내린 결정과 같은 형태이며, 답도 같다 — **드문 사건의 과잉 비용이, 모든 경로가 상시로 지는 분기 비용보다 싸다.**

**이 결정 덕분에 무효화 코드는 한 줄도 새로 쓰지 않는다.** 서명이 달라졌을 때 기존 경로가 실제로 어디까지 닿는지 따라가 확인했다.

| 단계 | 이미 있는 코드 | 확인한 동작 |
|---|---|---|
| 기동 | `_reconcile` 규칙 2 | `matches_index` 불일치 문서의 청크를 양쪽 색인에서 지우고 `chunk_count=0`·`stale` 로 커밋. 규칙 1이 잔여물을 회수 |
| 재업로드 | `_is_unchanged` → `Document.is_up_to_date` | `revision` 이 같아도 `is_searchable_under` 가 거짓이라 단축에 안 걸리고 색인 경로로 들어간다. `IngestionStatus.of` 가 `REINDEXED` |
| 이전 세대 | `_purge_previous` | `revision` 이 같을 때 선택자가 `{"index_signature": …}` 로 갈린다 — 이 분기가 정확히 이 경우를 위해 있다 |
| 캐시 | `derive_cache_key` · `derive_cache_scope` | **둘 다 `index_signature` 를 재료로 쓴다.** 서명이 바뀌면 L1 키도 L2 후보 집합의 이름도 달라져 옛 항목이 조회 범위 밖으로 나간다 |
| 되돌리기 | `CacheService._verify` | `markdown → plain → markdown` 으로 서명이 되돌아와 옛 캐시 항목이 다시 도달 가능해져도, 인용 문서를 `is_up_to_date` 로 재검증해 어긋나면 버린다 |

옛 서명의 캐시 항목은 TTL 까지 저장소에 남지만 어느 조회에도 걸리지 않는다 — 정확성이 아니라 공간의 문제다.

### 6. 두 구현의 공통 계약은 코드가 아니라 테스트가 묶는다

기존 파일을 고치지 않기로 했으므로 공통 로직을 상위 클래스나 헬퍼로 뽑지 않는다. 대신 **파서 계약 테스트를 두 구현으로 파라미터화**한다 — 쪽 번호, `empty_document` / `no_extractable_text` / `document_parse_error` 판정, 내부 예외 차단, 암호 PDF 거부.

상속으로 묶으면 코드 중복은 줄지만 두 라이브러리의 실패 표현이 다른 지점에서 훅(hook)이 늘어나고, 결국 분기가 상위 클래스로 옮겨 간다. 지켜야 하는 것은 구현의 공유가 아니라 **관측되는 계약의 동일성**이고, 그것을 직접 단언하는 것이 테스트다.

### 7. 파싱은 계속 스레드풀에서 돈다

마크다운 변환은 표 탐지(벡터 선 분석)를 하므로 평문 추출보다 무겁다. 파서가 동기라는 계약과 서비스가 스레드풀로 오프로드하는 구조는 그대로 두면 되고, 이 변경으로 이벤트 루프가 새로 막히는 자리는 없다. 수집 동시성 상한(`ingestion_concurrency`)도 그대로다.

## 계층형 인덱싱 검토 (이번 범위 밖, 후속 change 의 입력)

"부모-자식 계층형 인덱싱을 이 라이브러리로 할 수 있는가"를 검토했다. **결론: 라이브러리가 주는 것은 계층이 아니라 계층의 재료다.** 인덱싱 자체는 우리 청킹·검색 계층이 만들어야 한다. 다시 조사하지 않도록 확인한 사실을 남긴다.

**라이브러리가 실제로 주는 것**

| 것 | 내용 | 이번 change 에서 |
|---|---|---|
| `IdentifyHeaders` | 문서 전체의 폰트 크기 분포를 스캔해 크기 → 헤딩 레벨 맵을 만든다(`body_limit` 아래는 본문, 최대 6단계). `to_markdown` 의 기본 헤딩 판정이다 | **쓴다** — `#` · `##` 의 레벨 차이가 추출 결과에 나온다 |
| `TocHeaders` | 폰트 대신 PDF 목차(outline)로 헤딩을 판정한다. 목차가 있는 문서에서 더 정확하고 빠르다 | 안 쓴다(결정 3). 후속이 목차 있는 문서를 다룰 때 후보 |
| `toc_items` | 쪽 조각마다 `[레벨, 제목, 쪽번호]` 목록. 그 쪽을 가리키는 목차 항목이다 | 안 쓴다 — 담을 자리가 없다 |
| `tables` / `images` / `graphics` | 쪽 안 요소의 `bbox` 와 표의 행·열 수 | 안 쓴다 |

레이아웃 기반의 의미 단위 섹션(`page_boxes`)은 별도 컴포넌트(PyMuPDF Layout)가 판정하는데, **고정한 `1.28.0` 은 그것을 하드 의존성으로 끌고 온다** — 즉 후속 change 는 설치를 새로 하지 않고도 이 키에 손댈 수 있다. 다만 그것은 레이아웃 모드를 켜는 별도 호출이고, 이번 change 는 켜지 않는다.

**라이브러리가 주지 않는 것 = 후속 change 가 만들어야 하는 것**

1. **절 트리.** 마크다운 헤딩 레벨을 읽어 문서를 절 계층으로 세우는 로직. 재료는 있지만 트리는 없다.
2. **자식·부모 두 단위의 저장.** 자식(작게 잘라 임베딩되는 것)과 부모(검색 후 LLM 에 넘길 절 전체)를 어떻게 저장할지 — 부모를 벡터 없이 따로 둘지, 자식에 절 경로를 붙여 재조립할지. 지금 `Chunk` 에는 부모를 가리킬 필드가 없다.
3. **검색 후 확장.** 융합(RRF) 뒤 자식 히트를 부모로 올리고 중복 부모를 접는 단계. 지금 검색 경로에는 그런 단계가 없다.
4. **인용의 기준 변경.** 출처가 자식 청크인지 부모 절인지가 답변 응답의 모양을 바꾼다.

**범위 평가**

건드리는 스펙이 셋이다 — `document-ingestion`(저장 단위와 서명), `retrieval`(확장 단계와 결과 모양), `answer-generation`(인용 조립과 프롬프트에 실리는 텍스트). 새 `ChunkStrategy` 값과 `CHUNK_STRATEGY_VERSION` 상승이 따라오므로 **이번 change 의 서명 축과 겹친다.** 함께 하면 추출 변경과 분할 전략 변경이 한 서명 안에 섞여, 검색 품질이 달라졌을 때 어느 쪽 때문인지 말할 수 없다.

**이번 change 가 후속에 보장하는 것**: 추출 결과에 **헤딩 레벨이 관측 가능하게 남는다**(스펙 「기본 추출 방식은 PDF 의 구조를 마크다운으로 보존한다」). 후속은 추출 계층을 다시 열지 않고 그 위에서 시작한다.

## Risks / Trade-offs

**[헤딩·표 판정이 픽스처 PDF 에서 안 잡힐 수 있다]** → 변환기는 폰트 크기와 벡터 선으로 추정한다. 실제 문서에서 되는 판정이 합성 픽스처에서 안 될 수 있다. **픽스처를 먼저 만들어 눈으로 확인한 뒤 테스트를 쓴다**(tasks 1.x). 확인에 실패하면 테스트를 느슨하게 고치는 것이 아니라 **스펙을 고친다**(`/opsx:update`) — 스펙이 약속한 관측이 실제로 관측되지 않으면 그것은 테스트 문제가 아니라 허위 기재다.

**[마크다운 표기가 청크 예산을 잠식한다]** → 청크 크기는 문자 600 이다. 표 구분자와 헤딩 기호가 그 예산의 일부를 쓰므로 같은 PDF 에서 청크 수가 늘어난다. 수용한다 — 늘어난 청크 수는 저장 비용이고, 잃은 구조는 답변 정확도다.

**[표가 청크 경계에서 잘려 헤더 행을 잃을 수 있다]** → 헤더 행이 앞 청크에, 데이터 행이 뒤 청크에 남으면 뒤 청크만으로는 열의 의미를 알 수 없다. 겹침(100자)이 일부를 완화하지만 큰 표에서는 부족하다. **알려진 한계로 남기고 마크다운 인지 청킹을 후속 change 로 둔다** — 이번에 함께 하면 추출 변경과 분할 전략 변경이 한 서명 안에서 섞여, 검색 품질이 달라졌을 때 어느 쪽 때문인지 말할 수 없다.

**[기존에 수집된 모든 문서가 `stale` 이 된다]** → PDF 뿐 아니라 텍스트·마크다운 문서까지 서명이 달라져 재업로드가 필요하다(결정 5). 원본 바이트를 보관하지 않는 구조의 귀결이며, 평가 시나리오에서는 `sample-docs/` 재업로드로 끝난다. 마이그레이션 절차에 적는다.

**[추출 시간 증가]** → 표 탐지가 붙어 큰 PDF 의 추출이 느려진다. 업로드 응답이 그만큼 늦어지지만 동기 경로가 아니라 스레드풀이라 다른 요청은 막히지 않는다. 계측값이 `README.md` 에 적을 만큼 크면 그때 적는다.

**[의존성이 하나가 아니라 넷 늘어난다]** → `pymupdf4llm==1.28.0` 은 `pymupdf==1.28.0` 외에 `pymupdf_layout`·`tabulate` 를 하드 의존성으로 끌고 오고, `pymupdf_layout` 은 다시 `onnxruntime`·`numpy`·`networkx` 를 끈다. **이미지가 커지고 빌드가 길어진다.** 더 나쁜 경우는 레이아웃 모델을 첫 사용 시점에 받는 것인데, 그러면 평가자 환경에서 첫 업로드가 네트워크에 묶인다 — 이 리포가 sentence-transformers 모델을 빌드 단계에서 미리 받는 것과 같은 실패다. **구현 전에 확인한다**(tasks 1.1a): 이미지가 빌드되는지, 첫 추출이 네트워크 없이 끝나는지. 받는 것이 있으면 빌드 단계로 옮긴다.

**[`pymupdf` 바닥이 `1.24` 에서 `1.28.0` 고정으로 올라간다]** → 기존 `plain` 파서와 테스트 픽스처도 새 라이브러리 위에서 돈다. `page.get_text()` 의 출력이 미세하게 달라질 수 있으나, 이번 배포는 서명이 달라져 전 문서가 어차피 재색인되므로 옛 라이브러리로 뽑은 청크가 남지 않는다. 기존 파서 테스트가 그대로 통과하는지는 4.1 이 확인한다.

**[교체 지점이 하나가 아니게 된다]** → **"교체 지점은 파일 하나"라는 `ARCHITECTURE.md` 의 문장이 더 이상 참이 아니다** — 이제 파일 둘과 배선 한 곳이다. 같은 커밋에서 문서를 고친다.

## Migration Plan

0. **첫 배포에서는 `plain` 을 골라도 전 문서가 재색인된다.** 재료가 한 칸 늘어 서명 자체가 달라지기 때문이고, `plain` 의 추출 결과는 오늘과 같다. 결함이 아니라 서명의 정의가 작동하는 모습이다 — 되돌릴 수 있는 배포를 원한다면 이 한 번의 재색인은 피할 수 없다.
1. 새 의존성과 파서를 넣고 기본값을 `markdown` 으로 둔 채 배포한다.
2. 기존 `./data` 를 유지한 채 기동하면, 기동 정리가 서명 불일치를 발견해 모든 문서의 청크를 지우고 `index_status` 를 `stale` 로 표시한다. **오류가 아니라 설계된 경로다.**
3. `sample-docs/` 의 문서를 다시 업로드하면 새 추출 방식으로 재색인된다. `status` 가 `unchanged` 가 아니라 `reindexed` 로 나와야 정상이다.
4. **롤백**: `APP_PDF_EXTRACTION=plain` 으로 기동한다. 서명이 다시 달라지므로 재업로드가 한 번 더 필요하다 — 롤백은 코드 되돌리기 없이 되지만 데이터는 그냥 오지 않는다.

## Open Questions

- 표 탐지 전략(격자선만 볼 것인가, 여백 정렬까지 볼 것인가)의 기본값 조정은 실제 문서로 계측한 뒤 정해도 된다. 스펙이 요구하는 것은 "격자선으로 구분된 표"까지이므로, 더 느슨한 전략의 채택 여부는 스펙·태스크를 바꾸지 않는다.
