## Purpose

브라우저에서 문서를 수집하고, 질문에 대한 답변이 **조각 단위로 도착하는 과정**과 그 답변이 어느 문서의
어느 대목에 근거했는지를 확인하는 데모 화면의 계약을 규정한다. 화면은 서버 계약을 소비하기만 하며
새 사실을 만들지 않는다 — 화면에 보이는 모든 값은 서버 응답에서 온 것이어야 한다.

## ADDED Requirements

### Requirement: 데모 화면은 한 줄 명령으로 기동되고 서버 계약만 소비한다

데모 화면은 `README.md`에 적힌 **한 줄 명령**으로 기동되어야 한다 (**MUST**). 기동한 화면은 브라우저에서
API 서버와 **같은 출처**로 요청을 보내야 하며 (**MUST**), 그 요청이 API 서버로 전달되어야 한다 (**SHALL**).

데모 화면 때문에 API 서버의 코드·설정·기동 절차가 바뀌어서는 안 된다 (**MUST NOT**). 데모 화면은
`docker compose up` 기동 경로와 `pytest` 실행 경로 어느 쪽에도 끼어들어서는 안 된다 (**MUST NOT**).

화면이 표시하는 값은 전부 서버 응답에서 유래해야 하며, 응답에 없는 값을 화면이 지어내서는 안 된다
(**MUST NOT**). 서버가 아직 제공하지 않는 항목(예: 캐시 히트 여부)을 화면에 표시해서는 안 된다 (**MUST NOT**).

#### Scenario: 한 줄 명령으로 기동한다

- **WHEN** API 서버가 떠 있는 상태에서 `README.md`에 적힌 데모 화면 기동 명령을 그대로 한 번 실행한다
- **THEN** 브라우저에서 화면이 열리고, 문서 목록과 의존성 상태가 서버에서 받아온 값으로 채워진다

#### Scenario: API 서버는 변경되지 않는다

- **WHEN** 데모 화면 변경분을 적용한 뒤 API 서버를 기동하고 테스트 스위트를 실행한다
- **THEN** 기동 절차와 테스트 결과가 변경 전과 같고, `src/app/` 아래에 변경된 파일이 없다

#### Scenario: 서버가 주지 않은 값은 표시하지 않는다

- **WHEN** 화면이 표시하는 항목을 서버 응답 스키마와 대조한다
- **THEN** 모든 항목이 `/documents`·`/search`·`/qa`·`/health` 응답의 항목에 대응하며, 대응 없는 항목이 없다

### Requirement: 문서 패널이 수집·목록·삭제를 수행한다

화면은 수집된 문서 목록을 보여주어야 하며, 각 항목은 파일명·포맷·청크 수·색인 상태(`index_status`)를
표시해야 한다 (**SHALL**). 파일 선택과 드래그 앤 드롭 두 방법 모두로 업로드할 수 있어야 한다 (**MUST**).

업로드 응답의 처리 결과(최초 수집·교체·재색인·무변경)를 화면이 구분해 보여주어야 한다 (**MUST**) —
같은 파일을 다시 올렸을 때 무슨 일이 일어났는지가 드러나지 않으면 재수집 동작을 확인할 수 없다.
업로드·삭제가 성공하면 문서 목록이 서버 상태를 반영해 갱신되어야 한다 (**SHALL**).

문서가 하나도 없으면 빈 목록 대신 **무엇을 해야 하는지 알려주는 안내 상태**를 보여주어야 한다 (**MUST**).

업로드가 실패하면 서버 오류 봉투의 `code`에 대응하는 문구를 보여주어야 하며 (**MUST**),
최소한 지원하지 않는 포맷·용량 초과·추출 가능한 텍스트 없음 세 경우를 서로 구분해야 한다 (**MUST**).
실패한 업로드가 문서 목록을 바꿔서는 안 된다 (**MUST NOT**).

#### Scenario: 파일을 업로드하면 목록에 나타난다

- **WHEN** 지원 포맷 문서 하나를 파일 선택 또는 드래그 앤 드롭으로 업로드한다
- **THEN** 처리 결과가 "최초 수집"으로 표시되고, 문서 목록에 그 문서가 파일명·포맷·청크 수·색인 상태와 함께 나타난다

#### Scenario: 같은 문서를 다시 올린다

- **WHEN** 이미 수집된 문서와 내용이 같은 파일을 다시 업로드한다
- **THEN** 처리 결과가 "무변경"으로 최초 수집과 구분되어 표시되고, 문서 목록의 항목 수가 늘지 않는다

#### Scenario: 지원하지 않는 포맷을 올린다

- **WHEN** 지원하지 않는 확장자의 파일을 업로드한다
- **THEN** 포맷 미지원에 해당하는 문구가 표시되고, 문서 목록이 그대로다

#### Scenario: 문서를 삭제한다

- **WHEN** 문서 목록의 항목 하나를 삭제한다
- **THEN** 삭제 확인을 거친 뒤 그 항목이 목록에서 사라지고, 화면을 새로 고쳐도 다시 나타나지 않는다

#### Scenario: 수집된 문서가 없다

- **WHEN** 문서가 하나도 수집되지 않은 상태로 화면을 연다
- **THEN** 문서를 업로드하라는 안내 상태가 보이고, 질문 입력은 여전히 가능하다

### Requirement: 답변은 도착하는 즉시 화면에 반영된다

화면은 질문 하나에 대해 서버가 흘려보내는 이벤트를 **도착 순서대로 즉시** 반영해야 한다 (**MUST**).
답변 전체가 도착할 때까지 기다렸다가 한 번에 그려서는 안 된다 (**MUST NOT**) — 스트리밍이 실제로
동작하는지가 이 화면의 존재 이유다.

근거 목록은 첫 답변 조각보다 **먼저** 화면에 나타나야 한다 (**SHALL**). 종료 이벤트가 도착하면
소요 시간과 종료 사유를 표시해야 한다 (**SHALL**).

생성이 진행되는 동안 화면은 진행 중임을 드러내야 하고 (**MUST**), 사용자가 그 요청을 **중단**할 수
있어야 한다 (**MUST**). 중단하면 화면은 도착한 조각까지를 남기고 중단됨을 표시해야 하며, 서버로 향한
요청도 함께 끊어야 한다 (**MUST**).

진행 중에 새 질문을 보내면 이전 요청을 끊고 새 요청만 화면에 반영해야 한다 (**MUST**) — 두 스트림의
조각이 한 답변에 섞여서는 안 된다 (**MUST NOT**).

#### Scenario: 답변 조각이 순차적으로 도착한다

- **WHEN** 수집된 문서로 답할 수 있는 질문을 보낸다
- **THEN** 근거 목록이 먼저 나타나고, 답변 본문이 여러 번에 걸쳐 길어지며, 마지막에 소요 시간과 종료 사유가 표시된다

#### Scenario: 진행 중인 답변을 중단한다

- **WHEN** 답변이 흘러나오는 도중 중단을 누른다
- **THEN** 조각 추가가 멈추고, 이미 도착한 본문은 남으며, 중단됨이 표시되고, 이후 어떤 조각도 추가되지 않는다

#### Scenario: 진행 중에 새 질문을 보낸다

- **WHEN** 답변이 흘러나오는 도중 다른 질문을 보낸다
- **THEN** 이전 답변 영역이 새 질문의 것으로 교체되고, 이전 요청의 조각이 새 답변에 섞이지 않는다

### Requirement: 답변 본문의 인용 마커가 근거와 연결된다

종료 이벤트가 인용(`citations`)을 담아 오면, 화면은 답변 본문의 `[n]` 마커와 마커 번호가 같은 근거를
연결해 보여주어야 한다 (**MUST**). 근거 항목은 문서 파일명·청크 위치·유사도 점수를 표시해야 한다 (**SHALL**).

마커를 조작하면(클릭 또는 키보드 활성화) 해당 근거 항목으로 초점이 이동해야 한다 (**MUST**).

인용에 없는 마커 번호가 본문에 남아 있으면 그 마커를 근거로 연결해서는 안 되며 (**MUST NOT**),
버려진 마커가 있다는 사실(`dropped_markers`)을 표시해야 한다 (**SHALL**) — 프롬프트 회귀가 화면에서
드러나는 자리다.

근거 항목의 본문이 길면 잘려 보이되, 펼쳐서 전문을 볼 수 있어야 한다 (**MUST**).

#### Scenario: 마커에서 근거로 이동한다

- **WHEN** 인용이 포함된 답변에서 본문의 `[1]` 마커를 클릭하거나 키보드로 활성화한다
- **THEN** 1번 근거 항목으로 초점이 이동하고, 그 항목의 파일명·청크 위치·점수가 보인다

#### Scenario: 검증되지 않은 마커가 남는다

- **WHEN** 종료 이벤트의 `dropped_markers`가 0보다 큰 답변을 받는다
- **THEN** 버려진 마커 수가 화면에 표시되고, 그 번호의 마커는 근거로 연결되지 않는다

#### Scenario: 근거 본문이 길다

- **WHEN** 한 화면에 다 들어가지 않는 긴 청크가 근거로 온다
- **THEN** 접힌 상태로 표시되고, 펼치기를 조작하면 전문이 보이며, 가로 스크롤이 페이지 전체에 생기지 않는다

### Requirement: 근거가 없으면 답변 대신 거절 상태를 보여준다

근거 목록이 비어 있거나 종료 사유가 근거 부족일 때, 화면은 그 결과를 **답변이 아닌 별도 상태**로
보여주어야 한다 (**MUST**). 이 상태에서 화면이 답변 본문 영역을 채우거나 근거 없는 문장을 만들어
보여줘서는 안 된다 (**MUST NOT**) — 환각 억제가 화면에서도 지켜져야 한다.

거절 상태는 원인이 "수집된 문서가 없음"인지 "문서는 있으나 관련 근거가 없음"인지 구분해 보여주어야
한다 (**SHALL**).

#### Scenario: 수집된 문서와 무관한 질문을 한다

- **WHEN** 수집된 문서에 근거가 없는 질문을 보낸다
- **THEN** 답변 본문 대신 근거 부족 안내가 표시되고, 근거 목록이 비어 있으며, 어떤 문장도 답변으로 제시되지 않는다

#### Scenario: 문서가 없는 상태로 질문한다

- **WHEN** 수집된 문서가 하나도 없는 상태에서 질문을 보낸다
- **THEN** 문서를 먼저 업로드하라는 안내가 표시되고, 관련 근거 없음과 구분된다

### Requirement: 실패는 원인이 구분되는 문구로 드러난다

화면은 아래 실패를 서로 구분해 보여주어야 한다 (**MUST**).

| 실패 | 화면이 드러내야 할 것 |
|---|---|
| 요청 검증 실패 (빈 질의·길이 초과·K 상한 초과) | 무엇이 상한을 넘었는지와 그 상한 값 |
| 답변 생성기 미인증 | 인증이 없어서라는 사실과 재시도가 무의미하다는 것 |
| 답변 생성 실패·시간 초과 | 소진된 시도 수와 마지막 실패 사유 |
| API 서버에 닿지 못함 | 서버가 떠 있는지 확인하라는 안내 |

스트림이 시작된 뒤의 실패는 HTTP 상태가 아니라 스트림 안의 오류 이벤트로 도착하므로, 화면은 두 경로를
모두 처리해야 한다 (**MUST**). 종료 이벤트 없이 연결이 닫히면 화면은 그 사실을 실패로 표시해야 하며
(**MUST**), 진행 중 상태로 남겨두어서는 안 된다 (**MUST NOT**).

#### Scenario: 질의가 길이 상한을 넘는다

- **WHEN** 서버의 문자 수 상한을 넘는 질문을 보낸다
- **THEN** 상한을 넘었다는 문구와 상한 값이 표시되고, 답변 영역이 열리지 않는다

#### Scenario: 답변 생성기가 인증되지 않았다

- **WHEN** 생성기 인증이 없는 환경에서 질문을 보낸다
- **THEN** 근거 목록은 정상 표시되고, 답변 자리에는 인증 부재를 가리키는 문구가 표시되며, 다른 실패와 구분된다

#### Scenario: 서버에 닿지 못한다

- **WHEN** API 서버가 떠 있지 않은 상태에서 질문을 보낸다
- **THEN** 서버 연결 실패 안내가 표시되고, 화면이 진행 중 상태로 남지 않는다

#### Scenario: 스트림이 종료 이벤트 없이 끊긴다

- **WHEN** 답변이 흘러나오는 도중 연결이 끊긴다
- **THEN** 진행 중 표시가 사라지고 연결이 끊겼다는 문구가 표시되며, 도착한 조각은 남는다

### Requirement: 의존성 상태를 화면 상단에 표시한다

화면은 서버의 의존성 상태를 주기적으로 조회해 상단에 표시해야 한다 (**SHALL**). 표시는 의존성별로
이름과 상태를 담아야 하며 (**MUST**), 하나라도 정상이 아니면 그 사실이 눈에 띄어야 한다 (**MUST**).

상태 조회 자체가 실패하면 "알 수 없음"으로 표시해야 하며 (**MUST**), 마지막으로 성공한 상태를 계속
정상으로 보여주어서는 안 된다 (**MUST NOT**).

#### Scenario: 의존성이 모두 정상이다

- **WHEN** 모든 의존성이 정상인 서버에 연결한다
- **THEN** 상단에 정상 상태가 표시되고, 의존성 이름들이 각각 보인다

#### Scenario: 의존성이 불능이다

- **WHEN** 의존성 하나가 불능인 상태로 화면을 연다
- **THEN** 해당 의존성이 비정상으로 구분되어 표시되고, 전체 상태가 정상으로 보이지 않는다

#### Scenario: 상태 조회에 실패한다

- **WHEN** 상태 조회 요청이 실패한다
- **THEN** 상태가 "알 수 없음"으로 바뀌고, 직전의 정상 표시가 유지되지 않는다

### Requirement: 화면은 WCAG 2.2 AA 기준을 만족한다

모든 상호작용 요소는 키보드만으로 도달·조작 가능해야 하며 (**MUST**), 초점을 받은 요소는 배경과
대비 3:1 이상인 **보이는 초점 표시**를 가져야 한다 (**MUST**). 초점 표시를 제거해서는 안 된다 (**MUST NOT**).

본문 텍스트는 배경 대비 4.5:1 이상, 큰 텍스트와 UI 경계는 3:1 이상이어야 한다 (**MUST**).

스트리밍으로 갱신되는 답변 영역은 **보조 기술에 갱신이 통지되는 영역**이어야 하며 (**MUST**),
조각마다 통지가 쏟아지지 않도록 통지 단위를 조절해야 한다 (**SHALL**).

상태를 색만으로 구분해서는 안 된다 (**MUST NOT**) — 텍스트나 아이콘을 함께 둔다. 모든 조작 요소는
무엇이 일어나는지 알 수 있는 이름을 가져야 하며 (**MUST**), "클릭", "여기" 같은 이름을 써서는
안 된다 (**MUST NOT**).

사용자가 애니메이션 축소를 선호하면 전환 효과를 없애야 한다 (**MUST**).

모든 상호작용 컴포넌트는 기본·hover·focus-visible·active·disabled·loading·error 상태의 표현을
정의해야 한다 (**MUST**).

#### Scenario: 키보드만으로 전체 흐름을 수행한다

- **WHEN** 마우스를 쓰지 않고 탭 이동만으로 문서 업로드 → 질문 입력 → 전송 → 근거 이동을 수행한다
- **THEN** 모든 단계가 완료되고, 각 단계에서 초점 위치가 화면에 보인다

#### Scenario: 대비를 측정한다

- **WHEN** 화면의 본문 텍스트·큰 텍스트·UI 경계 대비를 측정한다
- **THEN** 본문이 4.5:1 이상, 큰 텍스트와 경계가 3:1 이상이다

#### Scenario: 스크린 리더가 답변 갱신을 알린다

- **WHEN** 스크린 리더를 켠 채 질문을 보낸다
- **THEN** 답변이 도착 중임과 완료됨이 통지되고, 조각마다 통지가 중복되지 않는다

#### Scenario: 애니메이션 축소를 선호한다

- **WHEN** 운영체제에서 동작 축소를 켠 상태로 화면을 연다
- **THEN** 전환 효과가 재생되지 않고, 상태 변화가 즉시 반영된다

### Requirement: 시각 스타일은 단일 토큰 출처에서만 나온다

색·타이포그래피·간격·모서리·그림자·모션 값은 **한 곳에 정의된 토큰**에서만 참조되어야 한다 (**MUST**).
컴포넌트 스타일이 토큰을 거치지 않은 원시 값(하드코딩된 색상 코드·픽셀 값)을 써서는 안 된다 (**MUST NOT**).

토큰 정의와 컴포넌트 상태 규칙·접근성 수용 기준·QA 체크리스트는 `demo-ui/DESIGN.md`에 문서화되어야
한다 (**MUST**). 문서에 적힌 토큰 이름과 값이 실제 정의와 어긋나서는 안 된다 (**MUST NOT**).

화면은 좁은 뷰포트(360px 폭)에서도 가로 스크롤 없이 사용 가능해야 한다 (**MUST**).

#### Scenario: 원시 값이 남아 있지 않다

- **WHEN** 컴포넌트 스타일에서 색상 코드와 간격 값을 찾는다
- **THEN** 토큰 정의 파일 밖에서 원시 색상 코드가 발견되지 않고, 간격 값이 전부 토큰 참조다

#### Scenario: 문서와 정의가 일치한다

- **WHEN** `demo-ui/DESIGN.md`에 적힌 토큰 이름·값을 토큰 정의 파일과 대조한다
- **THEN** 모든 이름이 정의에 존재하고 값이 같다

#### Scenario: 좁은 화면에서 사용한다

- **WHEN** 뷰포트 폭 360px에서 화면을 연다
- **THEN** 문서 패널과 Q&A 콘솔이 세로로 쌓이고, 페이지에 가로 스크롤이 생기지 않으며, 모든 조작이 가능하다
