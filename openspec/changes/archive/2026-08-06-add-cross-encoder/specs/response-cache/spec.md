## MODIFIED Requirements

### Requirement: 같은 질문의 두 번째 요청은 생성기를 부르지 않는다

서비스는 답변 생성 결과를 캐시해야 한다 (**SHALL**). 이미 캐시된 질문과 **같은 질문**이 다시 들어오면 생성기를 호출해서는 안 된다 (**MUST NOT**).

두 질의가 "같다"는 판정은 **정규화된 질의 문자열**로 한다. 정규화는 유니코드 정규화·앞뒤 공백 제거·연속 공백 축약·대소문자 통일을 포함해야 한다 (**MUST**). 그 이상으로 의미를 건드리는 변형(어간 추출, 불용어 제거, 조사 제거)을 해서는 안 된다 (**MUST NOT**) — 정확 매치 층은 "글자가 같다"를 판정하는 층이고, 의미의 근접은 유사 매치 층이 맡는다.

캐시 항목의 정체성은 정규화된 질의만으로 정해지지 않는다. 아래 재료 중 **하나라도 다르면 다른 항목**이어야 한다 (**MUST**):

| 재료 | 다를 때 일어나는 일 |
|------|--------------------|
| 정규화된 질의 문자열 | 다른 질문 |
| 검색 K (`top_k`) | 근거 개수가 달라 답변이 달라진다 |
| 프롬프트 버전 | 프롬프트를 고쳤는데 옛 프롬프트의 답이 나온다 |
| 색인 서명 | 청킹·임베딩 구성이 달라 근거가 달라진다 |
| 생성 모델 식별자 | 모델을 바꿨는데 이전 모델의 답이 나온다 |
| **리랭커 구성** | 상위 K에 다른 청크가 들어와 근거가 달라진다 |

리랭커 구성은 리랭킹이 **꺼진 상태와 켜진 상태를 구별해야 하며** (**MUST**), 리랭커 모델이 바뀌면 달라져야 한다 (**MUST**). 리랭커가 꺼진 배포에서 만들어진 항목이 켜진 배포에서 히트가 되어서는 안 된다 (**MUST NOT**).

캐시 키의 재료가 되는 질의는 **검색에 실제로 쓰인 질의**여야 한다 (**MUST**) — 사용자가 보낸 원문과 검색 질의가 갈리는 경우(질의 재작성 등)에는 후자가 키의 재료다. 원문으로 키를 잡으면 문맥이 다른 같은 문장이 같은 항목을 공유한다.

> 리랭커가 재료에 들어오는 근거는 색인 서명과 같다. 리랭킹은 **어떤 청크가 상위 K에 들어오는지**를 바꾸므로, 같은 질문이 리랭커 유무에 따라 다른 근거로 답해진다. 키가 그것을 모르면 리랭커 없이 만든 답변이 켜진 배포에서 그대로 나가고, 응답에 실린 `sources` 는 그 답변이 실제로 본 근거가 아니게 된다 — 인용이 답변을 뒷받침하지 않는데도 모든 검증이 통과한다.
>
> 리랭커를 **색인 서명에 합치지 않는** 이유는 수명이 다르기 때문이다. 색인 서명이 달라지면 저장된 청크가 `stale` 이 되어 재수집이 필요한데, 리랭커를 바꾸는 것은 저장된 것에 아무 영향도 주지 않는다. 합쳐 두면 리랭커 토글 한 번이 전 문서 재업로드를 요구하게 된다.

#### Scenario: 같은 질문을 두 번 보낸다

- **WHEN** 문서를 수집한 뒤 같은 질문을 연달아 두 번 보낸다
- **THEN** 두 요청 모두 `200` 으로 끝나고 답변 본문과 인용이 같으며, 생성기 호출 횟수가 정확히 `1` 이다

#### Scenario: 공백과 대소문자만 다른 질문은 같은 질문이다

- **WHEN** 어떤 질문을 보낸 뒤, 앞뒤 공백과 연속 공백과 대소문자만 다른 같은 문장을 보낸다
- **THEN** 두 번째 요청이 캐시 히트로 끝나고 생성기가 다시 호출되지 않는다

#### Scenario: K 가 다르면 다른 질문이다

- **WHEN** 어떤 질문을 `top_k=3` 으로 보낸 뒤, 글자가 같은 질문을 `top_k=5` 로 보낸다
- **THEN** 두 번째 요청이 캐시 미스로 처리되어 생성기가 다시 호출된다

#### Scenario: 프롬프트 버전이 바뀌면 이전 항목을 쓰지 않는다

- **WHEN** 어떤 질문의 답변이 캐시된 상태에서 프롬프트 버전이 바뀌고 같은 질문이 들어온다
- **THEN** 캐시 미스로 처리되어 생성기가 호출되고, 새 답변이 이전 항목을 대신한다

#### Scenario: 리랭커를 켜면 이전 항목을 쓰지 않는다

- **WHEN** 리랭커가 꺼진 구성에서 어떤 질문의 답변이 캐시된 뒤, 리랭커를 켠 구성에서 글자가 같은 질문이 들어온다
- **THEN** 캐시 미스로 처리되어 생성기가 호출된다

#### Scenario: 리랭커 모델이 바뀌면 이전 항목을 쓰지 않는다

- **WHEN** 어떤 질문의 답변이 캐시된 상태에서 리랭커 모델을 바꾸고 같은 질문이 들어온다
- **THEN** 캐시 미스로 처리되어 생성기가 호출된다
