## Why

검색·캐시 경로에서 결함 일곱 건이 확인됐다. 셋은 **판정이 틀리는** 결함이고(융합이 합의를 세지 못함, 유사 캐시가 부정문을 통과시킴, 후보 집합이 최신순이라 캐시가 클수록 못 맞힘), 넷은 **비용이 규모에 비례하는** 결함이다(요청당 임베딩 2회, 레지스트리 커넥션이 융합 목록 길이에 비례, 벡터 필터 조건 노드가 문서 수에 비례, `top_k`가 후보 집합을 불필요하게 쪼갬).

전부 오류를 내지 않고 조용히 나빠지는 종류다 — 검색은 계속 `200`을 내고, 캐시는 계속 히트라고 말한다. PRD §2(Query & Answer)와 §3(LLM 응답 캐싱)의 품질이 여기서 갈린다.

## What Changes

**판정**

- **융합 게이트 비대칭 제거.** 밀집 하한(코사인)과 어휘 변별력 판정이 지금은 후보 목록에서 항목을 **제거**한다. 두 목록이 서로 다른 기준으로 미리 잘려 교집합이 거의 생기지 않고, RRF가 합의에 주는 보너스가 발동하지 않는다 — 희소 토큰 하나로 우연히 걸린 청크가 코사인 0.85로 통과한 청크와 같은 융합 점수를 받는다. 게이트는 **제거 대신 표시**로 바꾸고, 융합 뒤 "자신을 실어 보낸 목록 중 최소 하나에서 게이트를 통과했는가"로 채택을 정한다. 단독 항목의 기준은 지금과 같고, 양쪽이 함께 올린 항목만 상대 게이트를 면제받는다.
- **유사 캐시에 어휘 게이트 추가.** "연차를 이월할 수 있나요"와 "연차를 이월할 수 **없**나요"는 코사인이 임계값을 넘어 L2 히트가 난다. 질의의 **부정 극성**을 캐시 항목의 속성으로 두고, 극성이 다른 항목은 유사도와 무관하게 후보에서 제외한다. **BREAKING**(내부 저장 형식): 캐시 페이로드 세대 표지를 올린다 — 기존 항목은 TTL로 사라진다.
- **`top_k`를 후보 집합 분리 기준에서 뺀다.** `top_k`는 캐시 **키**의 재료로는 남는다(근거 집합이 다르다). 하지만 K가 달라도 같은 질의는 유사 매치 후보로 유효하다. 히트 시 항목이 저장 시점에 쓴 K를 응답에 그대로 싣는다.

**비용**

- **유사 매치 후보를 근접 이웃 검색으로.** "최신순 200건 전수 스캔"을 Redis 8 Vector Sets로 옮긴다. 후보 상한은 남지만 그 상한이 **최신 N**이 아니라 **가장 가까운 N**을 뜻하게 된다 — 캐시가 커져도 히트율이 떨어지지 않는다. **BREAKING**(인프라): Redis 이미지가 7 → 8로 올라간다.
- **질의 임베딩을 요청당 1회로.** 캐시 조회가 만든 질의 벡터를 검색까지 흘려보낸다. 두 층이 **같은 문자열**을 임베딩하도록 정규화 규약도 하나로 맞춘다 — 캐시 상태에 따라 검색 결과가 달라지지 않게 하려면 이것이 조건이다.
- **현재성 재검증을 상위 K로 제한.** 지금은 융합 목록 전체(최대 200건)가 걸친 문서를 전부 다시 읽는다. 레지스트리 조회는 호출마다 SQLite 커넥션을 열므로, 문서 50개가 걸리면 질의 하나가 커넥션 50개를 동시에 연다. **절단 → 재검증 → 버려진 만큼 뒤에서 채움**으로 바꾼다. 결과는 지금과 같고 조회 수만 O(top_k)로 떨어진다.
- **벡터 필터를 조건 노드 하나로.** 대상 삼중항 목록이 지금은 문서당 조건 3개짜리 `$and`를 `$or`로 묶는다(문서 200개 → 노드 600개, 매 질의마다 조립·직렬화·평가). 청크 메타데이터에 삼중항을 합친 단일 키를 넣고 `$in` 하나로 바꾼다. 기동 정리가 이전에 저장된 청크의 메타데이터를 보정한다 — 재업로드를 요구하지 않는다.

## Capabilities

### New Capabilities

없음. 새 능력을 추가하지 않고 기존 능력의 판정 규칙과 비용 특성만 고친다.

### Modified Capabilities

- `retrieval`: 관련성 하한이 후보 목록의 필터가 아니라 채택 판정의 재료가 된다. 질의 임베딩이 요청당 정확히 1회이며 캐시 층과 같은 문자열을 쓴다. 현재성 재검증의 대상이 노출되는 상위 K로 한정된다.
- `lexical-index`: 변별력 판정이 어휘 목록에서 항목을 제거하지 않고 표시한다 — 최종 채택 규칙은 `retrieval`이 갖는다.
- `response-cache`: 유사 매치가 부정 극성이 다른 항목을 히트로 인정하지 않는다. 후보 집합이 `top_k`로 쪼개지지 않고, 히트 시 항목의 K가 응답에 실린다. 후보 상한이 최신순이 아니라 근접순으로 채워진다.
- `document-ingestion`: 기동 정리가 이전 세대 형식으로 저장된 청크 메타데이터를 현재 형식으로 보정한다.

**코드**

| 영역 | 파일 |
|---|---|
| 게이트 표시·채택 | `core/retrieval.py`, `adapters/retrievers/dense.py`, `adapters/retrievers/lexical.py`, `adapters/lexical/sqlite.py`, `services/retrieval.py` |
| 임베딩 1회 | `services/cache.py`, `services/retrieval.py`, `services/qa.py`, `adapters/retrievers/dense.py` |
| 재검증 절단 | `services/retrieval.py` |
| 캐시 극성·후보·스코프 | `core/cache.py`, `services/cache.py`, `adapters/cache/store.py`, `adapters/cache/memory.py`, `adapters/protocols.py` |
| 벡터 필터 | `core/documents.py`, `adapters/vector_store/chroma.py`, `services/ingestion.py` |

**의존성·인프라**

- `docker-compose.yml`: `redis:7-alpine` → `redis:8-alpine` (Vector Sets는 Redis 8의 자료형이다).
- `pyproject.toml`: `redis>=6.0` (Vector Set 명령 지원 버전).
- 설정: 밀집 하한·유사 임계값의 뜻은 그대로지만 유사 후보 상한(`APP_CACHE_SEMANTIC_CANDIDATES`)의 뜻이 "훑을 최신 항목 수"에서 "탐색할 근접 이웃 수"로 바뀐다.

**문서**

`ARCHITECTURE.md`(응답 캐시·검색 파이프라인·어휘 색인), `README.md`(Redis 버전 요구), `openspec/config.yaml`의 기술 스택 표를 함께 고친다 — 문서·구현 불일치는 감점, 허위 기재는 불합격이다.

**깨지는 것**

- 기존 Redis 캐시 항목은 히트하지 않고 TTL로 사라진다(세대 표지 상승). 정확성 문제는 없다.
- 기존 벡터 청크는 기동 정리의 메타데이터 보정을 거쳐 계속 검색된다. 보정이 실패하면 그 청크는 검색되지 않으므로, 실패를 조용히 넘기지 않고 로그로 드러낸다.
- `retrieval` 스펙의 시나리오 두 건("밀집 retriever가 올린 결과는 모두 하한 이상이다", "밀집 하한을 최대로 올려도 어휘 결과는 남는다")은 새 채택 규칙에서 성립하지 않아 다시 쓴다.
