## Why

`add-qa-retrieval`이 근거 후보까지 돌려준다. **그 근거로 답을 만드는 경로가 없다** — `AnswerGenerator` 같은 프로토콜도, LLM 어댑터도 존재하지 않는다. 지금 뚫려 있는 것은 실행 환경뿐이다: 이미지에 Node·`codex` CLI가 있고 자격증명이 볼륨으로 주입되지만, **컨테이너 안에서 CLI가 실제로 답변을 생성하는 코드는 한 줄도 없다**(`ARCHITECTURE.md` — "LLM SDK 통합 방식"이 그 사실을 명시하고 있다).

그래서 이 change가 닫는 구멍이 크다. PRD §2에서 검색을 뺀 나머지 전부(생성·출처 표기·**스트리밍**·환각 없는 처리)와 §4 프롬프트 설계가 통째로 여기에 있고, 평가 비중으로는 **LLM API 활용 18% + 프롬프트 엔지니어링 13% = 31%** 가 이 change 하나에 걸려 있다. RAG 파이프라인 23% 중 "답변 생성" 몫도 여기서 완성된다.

**캐싱을 함께 하지 않는 이유**는 순서 때문이다. 캐시 키와 무효화 축은 "답변 한 건이 무엇에 의존하는가"가 확정된 뒤에야 정할 수 있다 — 질문·`top_k`·인용된 문서의 `revision`·프롬프트 버전·모델 식별자 중 무엇이 키에 들어가는지는 이 change가 그 값들을 실제로 만들어 봐야 안다. 지금 캐시를 붙이면 아직 존재하지 않는 답변 파이프라인을 가정한 키를 설계하게 되고, 그 가정이 틀리면 캐시가 낡은 답을 계속 내보내는 형태로만 드러난다.

## What Changes

- **`AnswerGenerator` 프로토콜과 Codex 어댑터** — 프롬프트 문자열을 받아 답변 조각을 비동기로 흘려보내는 계약. 구현체는 `codex app-server`(stdio 위의 JSON-RPC) 세션을 띄워 `item/agentMessage/delta` 알림을 파싱한다. **지연 초기화**라 기동 경로는 CLI를 건드리지 않는다(기존 계약 유지 — `tests/test_boot.py`가 자격증명 없는 상태의 기동을 이미 고정하고 있다).

  **`codex exec`가 아니라 `app-server`인 이유는 실측이다.** `exec --json`에는 토큰 델타가 없어 4,808자 답변도 한 이벤트로 오는 반면, `app-server`는 209자 답변을 112개 델타로 흘린다. 덤으로 지연이 요청당 12~19초에서 4.5초로 줄고(세션을 살려 두면 `thread/start`의 8초가 사라진다), 인증 실패 판정이 문구 매칭에서 `httpStatusCode == 401`이라는 구조화된 값으로 바뀐다. 대가는 `app-server`가 `[experimental]` 표기라는 것이고, 계약이 안 바뀌므로 되돌리기는 어댑터 디렉터리 하나다. 근거 전체는 [`docs/superpowers/specs/2026-08-03-codex-app-server-streaming-design.md`](../../../docs/superpowers/specs/2026-08-03-codex-app-server-streaming-design.md).

- **`POST /qa` — SSE 스트리밍 엔드포인트.** 이벤트 시퀀스가 계약이다: `sources`(검색 결과, **LLM 호출 전에** 나간다) → `answer`(0회 이상, 이어 붙이면 답변) → `done`(최종 조립본과 종료 사유). 오류는 `done` 대신 `error` 하나로 끝난다. 스트림은 **항상 `done` 또는 `error` 정확히 하나**로 닫힌다.

- **거절을 두 갈래로 나눈다.** 지금까지 어느 계층도 "답할 수 없다"를 판정하지 않았다 — 검색은 빈 목록이나 낮은 점수로 드러내기만 하도록 못 박혀 있다. 그 판정이 여기서 처음 생기고, **두 사건은 서로 다르다**:
  - **근거가 0건** — LLM을 **호출하지 않는다**. 없는 문맥으로 모델에게 물으면 파라메트릭 지식이 답을 채우는 쪽으로 열리고, 그 위험을 감수할 이유가 없다. `finish_reason: "no_evidence"`. **서비스가 대신 문구를 쓰지도 않는다** — `answer`는 빈 문자열이고, 근거가 없다는 사실은 `finish_reason`이, 사용자에게 보일 표현은 소비자가 맡는다. 이로써 답변 문자열을 만드는 곳이 생성기뿐이라는 규칙에 예외가 사라진다.
  - **근거는 있는데 질문을 뒷받침하지 않는다** — **LLM이 판정한다**. 점수만으로는 알 수 없고 본문을 읽어야 하는 종류라, 유사도 하한이 아니라 프롬프트의 몫이다(`retrieval` 스펙이 그 경계를 이미 그어 두었다). `finish_reason: "insufficient_evidence"`.

- **출처는 마커로 흐르고 구조로 닫힌다.** 문맥 청크에 `[1]`..`[K]` 라벨을 붙여 넣고, 모델이 본문에 `[n]`을 남기며, `done` 이벤트가 그 마커를 **검증해** 구조화된 `citations` 배열로 조립한다. 존재하지 않는 번호는 버린다 — 없는 근거를 가리키는 인용은 환각이다. 인용 항목은 검색 결과를 그대로 읽어 만든다(`filename`·`revision`·페이지 또는 문자 오프셋).

- **LLM 호출에 timeout·retry를 건다.** 한 시도의 상한을 넘으면 프로세스를 죽이고, 지수 백오프로 재시도한다. **재시도는 `answer` 이벤트가 아직 하나도 나가지 않았을 때만 가능하다** — 한 조각이라도 나간 뒤의 재시도는 답변을 이어 쓰는 것이 아니라 처음부터 다시 쓰는 것이라 클라이언트에 중복이 도착한다. 스트리밍이 재시도 정책에 거는 제약이고, 이 change에서 처음 생긴다.

- **인증 부재는 재시도하지 않는 즉시 실패다.** 백오프를 몇 번 돌아도 자격증명이 생기지 않는다. 평가자 환경에서 가장 있을 법한 실패라 **오류 코드가 그 사실을 그대로 말해야** 한다 — "LLM이 불안정하다"로 뭉개면 평가자가 `.secrets` 경로를 확인할 이유를 못 찾는다.

- **프롬프트를 `core/`의 순수 함수로 둔다.** 문맥 조립·지시문·출력 형식이 표준 라이브러리만 쓰는 함수 하나에 모이므로, 프롬프트 회귀를 LLM 없이 문자열 단언으로 고정할 수 있다. 설계 의도는 `PROMPT_DESIGN.md`(PRD §4 산출물)에 적는다.

- **스트리밍 입자도를 실측하고 그 숫자를 문서에 남긴다.** 표면마다 다르다는 것이 실측의 결론이다 — `exec --json`은 메시지를 통째로 한 이벤트로 주고, `app-server`는 토큰 단위 델타를 준다. 계약을 **"`answer` 이벤트 0회 이상"** 으로 열어 둔 덕에 표면을 바꿔도 스펙과 서비스가 그대로다. **조각을 서버가 인위적으로 쪼개거나 합치지 않는다** — 생성기가 내보내는 단위를 그대로 전달한다. 쪼개는 것은 없는 진행을 만들어 내는 연출이고, 합치는 것은 실제로 앞당겨진 도착을 되돌리는 일이다.

- **설정 항목 추가** — 호출 상한, 최대 시도 수, 백오프 기준, SSE 하트비트 간격, 모델 식별자. 전부 기본값이 있어 "설정 없이 기동된다"는 기존 요구사항을 깨지 않는다.

## Capabilities

### New Capabilities

- `answer-generation`: 질문과 검색된 근거를 받아 LLM으로 답변을 생성해 **SSE로 흘려보내는** 계약. 이벤트가 어떤 순서로 오는지, 출처가 어떤 모양으로 실리는지, 근거가 없거나 무관할 때 무엇이 일어나는지, LLM이 느리거나 죽었거나 인증되지 않았을 때 스트림이 어떻게 끝나는지를 정한다.

### Modified Capabilities

없음.

- `retrieval` — 요구사항이 바뀌지 않는다. `/qa`는 기존 `RetrievalService`를 그대로 호출하며, `POST /search`도 그대로 남는다(답이 이상할 때 원인이 검색인지 생성인지 가르는 관측 지점이 그것이다 — `add-qa-retrieval` design 결정 8).
- `document-ingestion` — 닿지 않는다.

## Impact

**새로 생기는 것**

- `src/app/core/answers.py` — 답변·인용 값 객체, 종료 사유 (`core/`는 표준 라이브러리만)
- `src/app/core/prompting.py` — 프롬프트 조립 순수 함수, 모델 출력 파싱, 판정 줄 분리 상태 기계
- `src/app/services/qa.py` — 검색 호출 → 프롬프트 조립 → 생성 → 이벤트 스트림 조립, 재시도 정책
- `src/app/adapters/llm/session.py` — app-server 프로세스 하나의 수명·핸드셰이크·JSON-RPC 송수신·알림 라우팅
- `src/app/adapters/llm/pool.py` — 세션 풀(지연 기동, 상한, 죽은 세션 폐기와 교체)
- `src/app/adapters/llm/codex.py` — `AnswerGenerator` 구현. 턴 하나의 수명·델타 파싱·타임아웃·인증 판정
- `src/app/api/routes/qa.py` — `POST /qa` (SSE)
- `src/app/api/sse.py` — SSE 이벤트 직렬화와 하트비트 (형식은 HTTP 관심사다)
- `PROMPT_DESIGN.md` — **PRD §4 필수 산출물**
- `tests/` — 이벤트 시퀀스·거절 두 갈래·인용 검증·오류 3종·프롬프트 조립·판정 줄 분리·델타 알림 파싱·세션 풀 수명
- `tests/fake_app_server.py` — 프로세스 실패를 재현하는 가짜 app-server

**바뀌는 것**

- `src/app/adapters/protocols.py` — `AnswerGenerator` 추가 (기존 프로토콜 불변)
- `src/app/core/exceptions.py` — LLM 관련 오류 코드 추가 (기존 값은 건드리지 않는다)
- `src/app/api/errors.py` — 새 코드의 HTTP 상태 매핑
- `src/app/config.py` — 설정 항목 추가
- `src/app/main.py` — QA 서비스·생성기 배선
- `tests/stubs.py`·`tests/conftest.py` — 페이크 생성기와 QA 하네스
- `ARCHITECTURE.md` — "아직 없음"으로 적힌 LLM SDK 칸을 실제 통합으로 채우고, 실측한 스트리밍 입자도를 적는다
- `README.md` — `/qa` 사용법(`curl -N`)과 인증 없이 도는 테스트 실행 경로
- `openspec/project.md` — **기술 스택 표가 아직 `claude-code-sdk`로 적혀 있다.** `ARCHITECTURE.md`는 이미 Codex로 갈아탄 사실과 이유를 적고 있어, 두 문서가 지금 어긋나 있다. 이 change에서 맞춘다

**의존성**: 새 파이썬 패키지 없음(`codex`는 이미 이미지에 있고 표준 라이브러리 `asyncio.subprocess`로 띄운다). 새 컨테이너 없음. 프로세스는 요청마다 새로 뜨는 것이 아니라 **풀에서 재사용**되며, 상한은 `qa_concurrency`와 같아 동시 요청 수만큼 프로세스가 늘지 않는다.

**테스트 구성**: PRD §5의 3경로 중 이 change가 새로 만드는 것은 없지만(ingestion·retrieval은 이미 있고 캐시 무효화는 다음 change), **전 경로가 LLM 구독 없이 돌아야 한다는 제약은 여기서 처음 실질적인 부담이 된다.** 페이크 생성기가 조각·지연·오류를 스크립트로 재현하고, 델타 알림 파싱은 저장해 둔 실물 샘플로 검증한다. **프로세스 수명(타임아웃·사망·취소·핸드셰이크 실패)은 가짜 app-server 스크립트로 검증한다** — 실물 CLI로는 인위적으로 만들 수 없는 실패들이라, 이 층은 실물 층의 대체재가 아니라 실물 층이 닿지 못하는 곳이다. 실물 CLI를 부르는 테스트는 마커로 격리해 기본 실행에서 빠진다 — `pytest` 한 줄이 구독과 네트워크에 묶이면 안 된다는 기존 규율 그대로다.
