## Why

리포지토리가 백지 상태다. 이후 모든 기능은 "언제 체크아웃해도 `docker compose up` 한 줄로 뜨고 `pytest` 한 줄로 검증되는 서버" 위에 얹혀야 하는데, 지금은 그 바닥이 없다. 실행 불가는 감점이 아니라 불합격 사유이므로, 도메인 기능보다 실행 가능한 골격이 먼저다.

두 번째 이유는 인증 의존성이다. `claude-code-sdk`는 Claude Pro/Max 구독 인증에 의존한다. 인증이 없는 환경에서 서버가 기동조차 못 하면 평가자가 실행 절차를 1회 수행하는 순간 실행 불가로 판정된다. "인증 부재가 기동을 막지 않는다"는 성질은 나중에 붙이면 이미 여러 계층에 인증 전제가 스며든 뒤라 되돌리기 어렵다. 첫 change에서 못 박아둔다.

**PRD 대응**: §기술 조건(한 줄 실행 / 한 줄 테스트)을 직접 충족하고, §5 자동화 테스트의 하네스를 깐다. §1 Ingestion · §2 Query & Answer · §3 캐싱 · §4 프롬프트는 이 change에서 다루지 않는다.

## What Changes

- **FastAPI 앱 골격** — `api/` · `services/` · `core/` · `adapters/` 레이어 디렉터리와 앱 팩토리. 이후 change가 각 레이어에 얹기만 하면 되도록 경계를 먼저 만든다.
- **`GET /health`** — 서비스 자체의 응답 가능 여부와 백엔드 의존성(벡터 스토어, 캐시)의 도달 여부를 함께 보고한다. 의존성이 하나 죽어도 엔드포인트 자체는 응답한다.
- **설정 로딩** — 환경변수 기반. 의존성 접속 정보와 데이터 경로를 코드에서 분리한다.
- **에러 핸들링 골격** — 도메인 예외 기반 클래스와 전역 예외 핸들러. 어댑터 예외가 라우터로 새지 않는 경계를 처음부터 세운다.
- **구조화 로깅** — 요청 단위 로그. 이후 스트리밍·LLM 호출 디버깅의 전제.
- **Docker Compose** — API 컨테이너 + 캐시 컨테이너, 벡터 스토어 퍼시스턴트 볼륨. 한 줄로 기동.
- **자격증명 동기화 스크립트** — 호스트에 이미 있는 LLM CLI 자격증명을 컨테이너로 주입한다. 새로 발급하지 않고 기존 것을 재사용하며, 이 change에서는 주입 경로만 뚫고 CLI를 호출하지는 않는다.
- **pytest 하네스** — 앱 테스트 클라이언트 픽스처와 격리된 임시 저장소 픽스처. 헬스 경로 테스트 1개로 하네스가 실제로 도는지 증명한다.
- **문서 초판** — `README.md`(실행·테스트 절차), `ARCHITECTURE.md`(스택 선택 이유, 레이어 구조). 이 시점에 구현된 것만 적는다.

**명시적 비범위** — 문서 업로드, 텍스트 추출, 청킹, 임베딩, 벡터 검색, LLM 호출, 스트리밍 응답, 캐싱. 전부 이후 change에서 다룬다. 이 change는 범위를 넓히는 대신 "항상 실행되는 바닥"이라는 의도 하나만 지킨다.

## Capabilities

### New Capabilities

- `service-health`: 서비스의 기동 조건과 상태 리포팅. 어떤 조건에서 기동에 성공/실패하는지, 백엔드 의존성이 불능일 때 어떻게 보고하는지, 외부 인증 부재가 기동에 미치는 영향은 무엇인지를 규정한다.

### Modified Capabilities

없음. 첫 change라 기존 spec이 없다.

## Impact

**코드** — 전부 신규. `src/` 이하 레이어 디렉터리, 앱 팩토리, 헬스 라우터, 설정 모듈, 예외 기반 클래스, 어댑터 프로토콜 정의(구현체는 헬스 프로브에 필요한 최소한).

**의존성 추가** — FastAPI, ASGI 서버, 벡터 스토어 클라이언트, 캐시 클라이언트, pytest 및 테스트용 HTTP 클라이언트, ruff. `claude-code-sdk`와 임베딩 모델은 이 change에서 호출하지 않으므로 의존성 선언만 하고 로딩하지 않는다.

**인프라** — `docker-compose.yml`(API + 캐시 2개 서비스), `Dockerfile`, 벡터 스토어용 볼륨.

**문서** — `README.md`·`ARCHITECTURE.md` 신규 작성. 이후 change마다 갱신되므로, 지금은 구현된 범위만 적어 문서-코드 불일치를 만들지 않는다.

**이후 change에 남기는 계약** — 레이어 경계와 어댑터 프로토콜, 예외 처리 규약, 테스트 픽스처. ingestion·retrieval·QA·캐싱 change는 이 계약을 재사용하고 확장한다.
