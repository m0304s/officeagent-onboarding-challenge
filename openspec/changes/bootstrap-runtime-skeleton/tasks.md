- [x] 3.1 `core/`에 도메인 예외 기반 클래스 정의 — 프레임워크 의존 없음
- [x] 3.2 `core/`에 상태 값 객체 정의 — 의존성 개별 상태와 전체 상태
- [x] 3.3 `HealthProbe` 프로토콜 정의 (`name`, `check() -> ProbeResult`). 넓은 `VectorStore`·`CacheStore` 프로토콜은 정의하지 않는다 — design 결정 2
- [x] 3.4 캐시 저장소 프로브 구현 — 연결 후 ping, 개별 타임아웃, 실패 시 사유 요약
- [x] 3.5 벡터 스토어 프로브 구현 — 클라이언트 초기화 + 퍼시스턴스 경로 접근 가능 확인. 블로킹 I/O이므로 스레드풀로 오프로드. 클라이언트 객체 존재만 보고 정상 판정하지 않을 것 (design 결정 3)
- [x] 3.6 프로브 단위 테스트 — 정상 / 도달 불가 / 응답 없음(타임아웃) / **저장 경로에 쓸 수 없음** / **점검이 예상치 못한 예외를 던짐** 각각. 뒤의 둘이 3.5가 막으려는 실패 모드 본체다
- [x] 3.7 `ARCHITECTURE.md` 초판 — 스택 선택 이유, 레이어 구조, 어댑터를 프로토콜 뒤에 두는 이유와 좁게 정의한 이유

## 4. 헬스 서비스와 엔드포인트

- [x] 4.1 헬스 서비스 — 프로브 병렬 실행, 프로브별 타임아웃 + 전체 상한, 하나가 매달려도 나머지 결과 수집
- [x] 4.2 전체 상태 판정 — 필수 의존성이 모두 정상이면 정상, 하나라도 불능이면 불가용
- [x] 4.3 프로브가 도달 불가가 아닌 예외를 던져도 해당 프로브만 비정상 처리하고 나머지 결과는 보고 — 프로브 하나의 버그가 헬스 전체를 500으로 만들지 않게 (design 결정 4)
- [x] 4.4 `GET /health` 라우터 — 정상 200 / 불능 503. 두 경우 모두 같은 상태 보고 본문 구조를 쓰고, **공통 오류 봉투를 쓰지 않는다**. 의존성 목록은 정상 여부와 무관하게 항상 같은 집합
- [x] 4.5 앱 팩토리와 의존성 배선 — 모듈 전역 싱글턴 없이 주입 (테스트에서 교체 가능해야 함)
- [x] 4.6 헬스 시나리오 테스트 — 전체 정상 / 캐시만 불능 / 벡터 스토어만 불능 / 저장 경로 쓰기 불가 / **두 의존성 동시 불능** / 무응답 / **한쪽만 무응답이고 나머지는 정상** / **점검이 예외를 던짐**. 프로브 대역을 주입해 결정론적으로 구성 (spec 시나리오와 1:1)
- [x] 4.7 불능 시나리오에서 **어느 의존성이 문제인지 본문에서 식별되는지** 단언하는지 확인 — 상태 코드만 보는 테스트가 되지 않게
- [x] 4.8 503 본문이 공통 오류 봉투가 **아님**을 단언하는 테스트 — 두 형식이 섞이는 회귀를 막는다
- [x] 4.9 실패 사유 요약에 내부 정보(접속 문자열·스택 트레이스·자격증명)가 없음을 단언

## 5. 오류 처리와 로깅

- [x] 5.1 공통 오류 봉투 스키마와 `code` 열거값 정의 — 이후 change가 항목을 추가하는 확장 지점
- [x] 5.2 도메인 예외 → HTTP 응답 변환 핸들러. `api/` 계층에만 두고, 어댑터 예외가 라우터로 새지 않게
- [x] 5.3 미처리 예외 최종 핸들러 — 내부 정보(스택 트레이스·내부 식별자·접속 문자열)를 제거한 500, 원인은 로그에만
- [x] 5.4 프레임워크 기본 오류 응답(경로 없음·메서드 불허·요청 검증 실패)을 공통 봉투로 덮어쓰기 — 기본값을 두면 형식이 두 가지가 된다. **헬스 엔드포인트는 이 변환에서 제외** (design 결정 6)
- [x] 5.5 구조화 로깅 설정과 요청 단위 로그
- [x] 5.6 오류 경로 테스트 — 정의되지 않은 경로 / 허용되지 않은 메서드 / 요청 검증 실패 / 미처리 예외. 네 경우 모두 같은 봉투 형식이고 내부 정보가 없음을 단언

## 6. 컨테이너와 실행

- [x] 6.1 `Dockerfile` — 파이썬 런타임에 더해 LLM CLI 실행에 필요한 런타임과 CLI를 설치. **이 change에서는 호출하지 않는다** (design 결정 5)
- [x] 6.2 자격증명 동기화 스크립트 — 호스트의 **기존** 자격증명을 프로젝트 하위 비밀 디렉터리로 추출. 이미 파일로 존재하면 복사, macOS면 Keychain 항목에서 읽기. **새 토큰을 발급하는 명령은 쓰지 않는다** (design 결정 5-1의 제약). 퍼미션 0600, 평가자가 실행하는 명령은 OS와 무관하게 하나
- [x] 6.3 비밀 디렉터리를 `.gitignore`에 추가하고, 빈 상태로도 기동되는지 확인 — 자격증명이 리포에 커밋되지 않게
- [x] 6.4 `docker-compose.yml` — API + 캐시 저장소 2개 서비스, 벡터 스토어 퍼시스턴트 볼륨, 자격증명 파일을 **쓰기 가능하게(rw)** 마운트. 읽기 전용으로 붙이면 토큰 갱신에 실패해 약 8시간 뒤 인증이 끊긴다
- [x] 6.5 기동 시 자격증명 동기화가 자동으로 선행되도록 실행 진입점 구성 (예: `make up`) — 컨테이너가 항상 호스트의 최신 자격증명으로 시작
- [x] 6.6 워커 프로세스를 1개로 고정하고 이유(임베디드 벡터 스토어 파일 락)를 설정에 주석으로 남김
- [x] 6.7 캐시 컨테이너 자체 헬스체크 + API 기동 유예 설정 — 503 헬스와 얽힌 재시작 루프 방지
- [x] 6.8 자격증명 파일이 **없는** 상태로 기동 1회 수행 — 기동 성공과 `/health` 200을 눈으로 확인 (spec의 "인증 없이 기동" 요구사항 실물 검증)
- [x] 6.9 자격증명 파일이 **손상·판독 불가**한 상태에서도 기동과 `/health` 200이 성립하는지 테스트 — 부팅 경로가 자격증명을 파싱하지 않는다는 성질을 회귀로 고정
- [x] 6.10 실행 절차 한 줄 명령이 무엇인지 `README.md`에 못박기 — 자격증명 동기화를 감싼 진입점(6.5)이 그 명령이며, `docker compose up`을 직접 쓰면 동기화가 생략된다는 점을 명시
- [x] 6.11 자격증명 동기화 방법과 주의사항을 `README.md`에 기록 — refresh token 회전 시 호스트 CLI가 로그아웃될 수 있다는 경고 포함
- [x] 6.12 `ARCHITECTURE.md`에 LLM SDK 통합 방식 절 추가 — CLI 의존성, 자격증명을 이미지에 굽지 않고 기존 것을 주입하는 이유, 부팅 경로에서 CLI를 실행하지 않는 이유. **컨테이너 안에서 CLI가 실제로 동작하는지는 아직 검증되지 않았다는 사실을 명시** (허위 기재 방지)
