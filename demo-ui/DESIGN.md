# 데모 콘솔 UI 가이드라인

## 1. 컨텍스트와 목표

문서를 올리고, 질문에 대한 답변이 **조각 단위로 도착하는 과정**과 그 근거를 한 화면에서 확인하는
데모 콘솔의 구현 기준.

이 화면은 제품이 아니라 **검증 수단**이다. `curl -N` 으로는 조각의 도착 시각도, 본문의 `[n]` 과
서버가 검증한 인용의 대응도 눈에 보이지 않는다. 그 둘을 보이게 만드는 것이 존재 이유다.

관측 가능한 동작의 계약은 `openspec/changes/add-demo-ui/specs/demo-console/spec.md` 에 있고,
구조 결정과 그 근거는 `openspec/changes/add-demo-ui/design.md` 에 있다. 이 문서는 **시각·상호작용
규칙**만 다룬다.

### 원칙

- 화면에 보이는 값은 전부 서버 응답에서 온 것이어야 한다 (**MUST**). 화면이 값을 지어내지 않는다.
- 컴포넌트는 의미 토큰만 참조해야 한다 (**MUST**). 원시 값을 직접 쓰지 않는다.
- 모든 상호작용 컴포넌트는 7상태를 정의해야 한다 (**MUST**): default · hover · focus-visible ·
  active · disabled · loading · error.
- 시스템 일관성을 국소적 예외보다 우선해야 한다 (**should**).

### 브랜드 브리프와의 관계

제공된 브리프는 표면을 "e-commerce storefront"·"online shoppers" 로 적었지만, 브리프 자체가 그
추론의 신뢰도가 낮다고 표기했고 이 리포는 상거래 화면이 아니다. **토큰·접근성 규칙·문서 구조는
그대로 따르고 표면만 "문서 Q&A 데모 콘솔" 로 바꿔 적용했다.** 브리프가 제시한 컴포넌트 밀도
(links 94 / buttons 89 / cards 15 / navigation 12 / lists 2 / inputs 1)는 상거래 랜딩의 실측치라
이 화면에 이식하지 않았다 — 여기 필요한 것은 입력 1개, 버튼 6종, 카드 3종이다.

## 2. 파운데이션과 토큰

정의는 `src/styles/tokens.css` 한 파일에만 있다. **원시 층**(브리프 값 그대로)과 **의미 층**
(컴포넌트가 참조하는 이름) 둘로 나눴다. 브리프의 이름이 역할이 아니라 모양을 가리키기 때문이다 —
`surface.raised` 는 어두운 화면에서 "올라온 면" 이 아니라 밝은 회색 카드다.

### 2.1 색 — 실측 대비율

측정은 WCAG 2.x 상대휘도 공식. 괄호 안은 `--color-bg-page`(#000000) / `--color-bg-panel`(#111826)
위에서의 비율이다.

| 의미 토큰 | 값 | on page | on panel | 용도와 판정 |
|---|---|--:|--:|---|
| `--color-text-body` | `#eaeaea` | 17.46 | 14.76 | 본문. AA 4.5:1 통과 |
| `--color-text-strong` | `#ffffff` | 21.00 | 17.76 | 제목. 통과 |
| `--color-text-muted` | `#9ea6b6` | 8.58 | 7.26 | 보조 문구. 통과 |
| `--color-text-on-inverse` | `#333333` | — | 9.30 (on `#dddddd`) | 밝은 면 위 글자. 통과 |
| `--color-accent` | `#7cb0ff` | 9.51 | 8.04 | 기본 액션·링크·마커 |
| `--color-success` | `#4ade80` | 12.05 | 10.19 | 정상 상태 |
| `--color-warning` | `#fbbf24` | 12.58 | 10.64 | 주의·미인증 |
| `--color-danger` | `#ff9b9b` | 10.41 | 8.81 | 오류·삭제 |
| `--color-focus-ring` | `#a8c7ff` | 12.28 | 10.38 | 초점 링. 3:1 요구를 크게 상회 |
| `--color-border-control` | `#5c6678` | 3.63 | 3.07 | **조작 요소 경계.** 1.4.11(3:1) 통과 |
| `--color-border-strong` | `#e5e7eb` | 16.96 | 14.34 | hover·강조 경계 |
| `--color-border-subtle` | `#171e2c` | 1.26 | 1.06 | **장식용 구분선 전용** |

`--color-border-subtle` 은 3:1 에 한참 못 미친다. 그래서 **조작 요소의 경계로 쓰면 안 된다**
(**MUST NOT**). 이 토큰이 놓이는 자리는 채워진 두 면 사이의 헤어라인뿐이고, 그 경계가 없어도
컴포넌트를 식별할 수 있어야 한다. 조작 요소는 `--color-border-control` 이상을 쓴다 (**MUST**).

### 2.2 브리프 값에서 조정한 것

그대로 쓸 수 없던 항목과 처리. **원시 값은 전부 보존했고, 조정은 의미 층에서만 했다.**

| 브리프 | 문제 | 처리 |
|---|---|---|
| `color.border.muted` = `rgb(23,30,44) rgb(229,231,235)` | 값이 둘이라 단일 토큰이 못 된다 | 어두운 면용 `#171e2c` 를 `--color-border-subtle` 로, 밝은 값 `#e5e7eb` 를 `--color-border-strong` 으로 분리 |
| 강조색 없음 | 기본 액션·성공·주의·오류를 구분할 수단이 없다 | 상태 색 4종 + 초점 링을 신규 정의하고 대비를 실측해 위 표에 기록 |
| 경계색이 전부 1.26 또는 16.96 | 3:1 부근의 "차분한 경계" 단이 없다 | `--color-border-control`(#5c6678, 3.63/3.07) 신규 |
| `font.size` 16 → 18 → 56 → 86 | 카드·섹션 제목에 쓸 단이 비어 있다 | 원시 보존 + `--font-size-heading: 20px`, `--font-size-title: 28px`, `--font-size-caption: 14px` 파생 |
| `font.weight.base` = 600 | 장문 본문에 600 은 읽기 부담이다 | 본문만 `--font-weight-body: 400`, 브리프 값은 `--font-weight-emphasis: 600` 으로 유지 |
| `space` 최소 단이 10px | 배지 안쪽·목록 항목 사이를 채울 수 없다 | 컴포넌트 내부 전용 `--space-tight-1/2/3` = 2/4/6px 파생 |
| `radius` 최소 단이 10px | 초점 링·인라인 칩에 쓸 단이 없다 | `--radius-hairline: 2px`, `--radius-chip: 4px` 파생 |
| `motion.duration.instant` = 300ms | 300ms 는 즉각이 아니다 | 값 보존, 이름을 `--motion-duration-base` 로. 마이크로 전환용 `--motion-duration-fast: 120ms` 추가 |

### 2.3 간격 규율

- 컴포넌트 **내부** 간격은 `--space-tight-1/2/3` 과 `--space-2xs`~`--space-lg`(10~28px)만 쓴다 (**MUST**).
- `--space-page-sm/md/lg`(80/120/140px)는 **페이지 여백 전용**이다 (**MUST**). 컴포넌트가 이 단을
  쓰기 시작하면 360px 뷰포트에서 콘텐츠가 사라진다.
- 새 간격 값을 컴포넌트에 직접 적지 않는다 (**MUST NOT**). 필요하면 토큰을 늘리고 여기 기록한다.

### 2.4 타이포그래피

`Pretendard` 를 `@fontsource/pretendard` 로 **번들에 넣는다** (400·600). CDN `@import` 를 쓰지
않는다 (**MUST NOT**) — 오프라인이나 CDN 이 막힌 환경에서 조용히 폴백되면 대비·줄바꿈 검증이
통째로 흔들린다. 실측 페이로드는 woff2 **765.9KB(400) + 785.9KB(600)** 이다. 이 패키지는 서브셋이
하나뿐이고 이름과 달리 한글 전체를 담고 있어 줄일 여지가 없다. `font-display: swap` 이라 첫
페인트를 막지 않고, 데모는 localhost 에서 도는 것이 전제라 이 크기를 받아들였다.

한국어 본문에는 `word-break: keep-all` 과 `overflow-wrap: break-word` 를 함께 건다 (**MUST**).
기본 규칙은 어느 글자에서나 줄을 바꿔 **단어 가운데가 잘린다.**

### 2.5 예외 하나

`.srOnly` 의 `margin: -1px` 만 토큰을 거치지 않는다. 표준 visually-hidden 관용구의 일부이고
간격 선택이 아니라 클리핑 장치라서다. **이것이 토큰 규칙의 유일한 예외다.** 다른 예외를 늘리려면
이 절에 근거와 함께 적어야 한다 (**MUST**).

검증:

```bash
grep -rnE '#[0-9a-fA-F]{3,8}|rgba?\(' --include='*.css' demo-ui/src | grep -v tokens.css   # (없음)
grep -rnE '(padding|margin|gap|border-radius):[^;]*[0-9]+px' --include='*.css' demo-ui/src \
  | grep -v tokens.css                                                                      # .srOnly 한 줄만
```

## 3. 컴포넌트 규칙

### 3.1 Button (`ui/Button.tsx`)

**Anatomy** — `[스피너?] + 라벨`. 최소 높이 44px(터치 표적), 좌우 `--space-sm`.

**Variants** — `primary`(강조 배경, 글자는 `--color-text-on-inverse`) · `secondary`(기본, 외곽선) ·
`danger`(오류색 외곽선) · `ghost`(경계 없음, 최소 높이 32px).

| 상태 | 표현 |
|---|---|
| default | `--color-border-control` 경계 |
| hover | 경계 `--color-border-strong`, 배경에 본문색 10% 혼합 |
| focus-visible | 전역 초점 링 2px + offset 2px |
| active | 배경 혼합 18% |
| disabled | `opacity: 0.45`, `cursor: not-allowed` |
| loading | 스피너 표시, `disabled` 와 `aria-busy` 동시 적용, `cursor: progress` |
| error | `invalid` prop → `--color-danger` 경계 + `aria-invalid` |

- 진행 중 버튼은 `disabled` 여야 한다 (**MUST**) — 중복 제출이 스트림을 두 개 만든다.
- 라벨은 무엇이 일어나는지 말해야 한다 (**MUST**). "클릭"·"여기"·"확인" 같은 라벨을 쓰지 않는다
  (**MUST NOT**). 아이콘만 있는 버튼에는 `aria-label` 을 붙인다 (**MUST**).

**키보드** Enter·Space 로 활성화(네이티브). **포인터** 44px 이상 표적. **터치** 표적 간
`--space-2xs` 이상 간격.

### 3.2 Badge (`ui/Badge.tsx`)

**Anatomy** — `[점?] + 라벨`. tone 은 `neutral|ok|warn|danger|info`.

- 상태를 색만으로 구분하지 않는다 (**MUST NOT**). 점은 장식이고 라벨 텍스트가 항상 함께 있어야
  한다 (**MUST**). 색각 이상과 흑백 인쇄에서 같은 정보를 읽을 수 있어야 한다.
- 배지는 조작 요소가 아니라 초점을 받지 않는다. hover·active 상태를 정의하지 않는다.

### 3.3 Dropzone (`Dropzone.tsx`)

**Anatomy** — 점선 영역 + `label`(시각적 버튼) + 숨은 `input[type=file]` + 안내 문구 + 지원 형식.

트리거를 `label` + 숨은 `input` 으로 두는 이유는 그 조합이 **키보드 조작과 접근 가능한 이름을
브라우저에게서 공짜로 받기** 때문이다. `div` + `onClick` 으로 만들면 둘 다 직접 구현해야 한다.

| 상태 | 표현 |
|---|---|
| default | 점선 `--color-border-control` |
| hover | 경계 `--color-border-strong` |
| focus-visible | `:has(input:focus-visible)` 로 컨테이너에 초점 링을 그린다 |
| dragging | 실선 강조색 + 강조색 12% 배경, 문구가 "여기에 놓으세요" 로 바뀜 |
| disabled | `opacity: 0.5`, 입력 비활성 |
| loading | 업로드 중에는 `disabled` 로 취급 |
| error | 실패 문구는 Dropzone 이 아니라 패널의 오류 영역이 표시 |

- `dragenter`/`dragleave` 는 자식 요소를 지날 때마다 발생하므로 **깊이를 세야 한다** (**MUST**).
  세지 않으면 테두리가 깜빡인다.
- 같은 파일을 연속으로 고를 수 있게 `change` 후 `value` 를 비운다 (**MUST**).

### 3.4 DocumentRow (`DocumentRow.tsx`)

**Anatomy** — `파일명 + 색인 상태 배지` / `형식·청크·크기·수집시각` / `삭제`.

- 긴 파일명은 한 줄로 자르고 `title` 로 전문을 남긴다 (**MUST**). 360px 에서 가로 스크롤이 생기는
  첫 원인이 파일명이다.
- 삭제는 **확인 단계를 거쳐야 한다** (**MUST**). 확인 UI 는 같은 행 안에서 펼쳐지고, `window.confirm`
  을 쓰지 않는다 (**MUST NOT**) — 모달 대화상자는 스타일을 못 입히고 스크린 리더 흐름을 끊는다.
- 수집 시각은 연도를 빼고 표시한다. 좁은 패널에서 구분에 필요한 것은 월·일·시각이다.

### 3.5 QuestionForm (`QuestionForm.tsx`)

**Anatomy** — 라벨 + `textarea`(3줄) + 글자 수 + `[중단?]` + 제출.

| 상태 | 표현 |
|---|---|
| default | `--color-border-control` |
| hover | `--color-border-strong` |
| focus-visible | 전역 초점 링 |
| disabled | `opacity: 0.5` |
| loading | 제출이 스피너 + "답변 받는 중", 중단 버튼이 나타남 |
| error | 상한 초과 시 `--color-danger` 경계 + `aria-invalid` + 글자 수 빨강 |

- **Enter 로 전송, Shift+Enter 로 줄바꿈.** 단 `isComposing` 중의 Enter 는 가로채지 않는다
  (**MUST**) — 한글 IME 에서 그 Enter 는 조합을 확정하는 키라, 가로채면 마지막 글자가 잘린 채 전송된다.
- 글자 수는 서버 상한(1,000자)과 같은 값으로 세고, 넘으면 전송을 막는다 (**MUST**). 서버도 422 로
  막지만 화면에서 미리 알려야 한다.
- 빈 질의는 전송할 수 없어야 한다 (**MUST**).

### 3.6 SourceList (`SourceList.tsx`)

**Anatomy** — 제목 + 요약 배지 / 항목마다 `파일명 + 유사도` · 본문 미리보기 · `위치 + 펼치기`.

- 근거 목록은 **첫 답변 조각보다 먼저** 나타나야 한다 (**MUST**). 검색이 생성보다 빠르다는 사실이
  화면에 드러나야 한다.
- 본문 220자를 넘으면 접고 펼치기를 제공한다 (**MUST**). 토글에는 `aria-expanded` 를 붙인다 (**MUST**).
- 청크 본문은 원문이라 `white-space: pre-wrap` 으로 줄바꿈을 살린다.

### 3.7 AnswerStream / AnswerText / CitationList

**Anatomy** — `답변` 제목 + 소요시간·버려진 마커 배지 / 본문(+커서) / 인용 목록.

- 조각은 **도착 즉시** 반영해야 한다 (**MUST**). 전부 모아 한 번에 그리면 이 화면의 존재 이유가 없다.
- 스트리밍 중에는 `[n]` 이 **전부 평문**이어야 한다 (**MUST**). 인용은 `done` 이 와야 확정되고,
  검증 전 마커를 링크로 만들면 근거가 아닌 것이 근거인 척한다.
- `done` 이후에는 **`citations` 에 있는 번호만** 링크가 된다 (**MUST**). 없는 번호는 평문으로 남기고
  지우지 않는다 (**MUST NOT**) — 지우면 흘러간 문장과 최종 문장이 달라진다.
- `dropped_markers > 0` 이면 그 수를 배지로 표시해야 한다 (**MUST**). 프롬프트 회귀의 가장 이른 신호다.
- 인용 항목은 `id="citation-N"` 과 `tabIndex={-1}` 을 함께 가져야 한다 (**MUST**). `tabIndex` 가
  없으면 앵커 이동이 초점을 옮기지 못해, 스크린 리더 사용자에게는 아무 일도 안 일어난 것이 된다.
- 마커는 `button` 이 아니라 `a[href="#citation-N"]` 이다. "문서 내 이동" 이 정확히 앵커의 의미이고
  키보드 활성화·초점 이동·`:target` 강조를 브라우저에게서 받는다.

### 3.8 StatusBanner (`StatusBanner.tsx`)

거절 3종과 실패 6종을 **서로 다른 문구**로 표시한다 (**MUST**). 좌측 3px 색 띠 + 제목 + 설명.

| 종류 | 판정 근거 | 톤 |
|---|---|---|
| 문서 없음 | `sources.target_documents === 0` | neutral |
| 관련 근거 없음 | `finish_reason: no_evidence`, 대상 문서 ≥ 1 | neutral |
| 근거 부족 | `finish_reason: insufficient_evidence` | neutral |
| 요청 검증 실패 | HTTP 422 계열 코드 + 상한 값 | warn |
| 미인증 | `reason: unauthenticated` 또는 `llm_unauthenticated` | warn |
| 생성 실패·시간 초과 | `reason: timeout \| generation_failed` + 시도 수 | danger |
| 서버 미도달 | `network_unreachable` | danger |
| 연결 끊김 | 종료 이벤트 없이 스트림 종료 | danger |
| 중단 | 사용자 취소 | neutral |

- 실패에는 `role="alert"`, 거절·중단에는 `role="status"` 를 쓴다 (**MUST**).
- 검증 실패는 **상한 값을 함께** 보여야 한다 (**MUST**). "너무 깁니다" 만으로는 얼마나 줄일지 모른다.

### 3.9 HealthBadge (`HealthBadge.tsx`)

- 상태 코드가 아니라 **본문의 `status`·`dependencies`** 를 읽는다 (**MUST**). `/health` 는 200 과
  503 의 본문 모양이 같고, 503 을 예외로 던지면 어느 의존성이 죽었는지가 사라진다.
- 조회가 실패하면 즉시 "상태 알 수 없음" 으로 덮는다 (**MUST**). 마지막 성공값을 유지하면 서버가
  죽은 화면이 계속 초록으로 보인다 (**MUST NOT**).
- 의존성 키는 서버가 주는 이름 그대로 매핑한다 (`cache`, `vector_store`). 모르는 키는 키 이름을
  그대로 보여준다 — 서버가 프로브를 늘려도 화면이 조용히 누락하지 않는다.

### 3.10 반응형

| 폭 | 레이아웃 |
|---|---|
| < 960px | 문서 패널과 콘솔이 세로로 쌓임. 페이지 여백 `--space-md` |
| ≥ 960px | `380px + 나머지` 2열. 페이지 여백 `--space-page-sm` |

360px 에서 가로 스크롤이 생기면 안 된다 (**MUST NOT**). 위험 지점 넷: 긴 파일명(줄임표), 긴 청크
본문(`pre-wrap` + `break-word`), 메타 그리드(`auto-fit minmax(96px,1fr)`), 버튼 줄(`flex-wrap`).

### 3.11 빈 상태·오버플로

- 문서 0건 → 무엇을 해야 하는지 말하는 안내와 `sample-docs/` 위치 (**MUST**).
- 질문 전 → 무엇이 일어날지 예고하는 안내 (**MUST**).
- 근거 0건 → 목록을 숨기고 거절 배너만 (**MUST**).
- 목록을 "0건" 이라고만 적고 끝내지 않는다 (**MUST NOT**).

## 4. 접근성 — 검증 가능한 수용 기준

목표는 **WCAG 2.2 AA**. 각 항목은 통과/실패를 판정할 수 있어야 한다.

| # | 기준 | 통과 조건 | 실패 조건 |
|---|---|---|---|
| A1 | 키보드 도달 | 탭만으로 업로드 → 질문 → 전송 → 근거 이동 전 과정 완료 | 어느 한 단계라도 마우스가 필요 |
| A2 | 초점 가시성 | 모든 초점 요소에 2px 링, 배경 대비 ≥ 3:1 | 링이 없거나 잘림 |
| A3 | `outline: none` 부재 | 코드베이스 전체 검색 결과 0건 | 1건 이상 |
| A4 | 본문 대비 | 본문 ≥ 4.5:1 | 미만 |
| A5 | 경계 대비 | 조작 요소 경계·큰 텍스트 ≥ 3:1 | 미만 |
| A6 | 색 단독 의존 부재 | 모든 상태에 텍스트 라벨 동반 | 색만으로 구분되는 상태 존재 |
| A7 | 스트리밍 통지 | 전이(검색→생성→완료)마다 1회 통지 | 조각마다 통지, 또는 통지 없음 |
| A8 | 실패 통지 | 실패가 `role="alert"` 로 즉시 통지 | 조용히 표시만 |
| A9 | 접근 가능한 이름 | 모든 조작 요소가 서술적 이름 보유 | "클릭"·"여기" 또는 이름 없음 |
| A10 | 동작 축소 | `prefers-reduced-motion: reduce` 에서 전환·애니메이션 정지 | 그대로 재생 |
| A11 | 앵커 초점 이동 | 마커 활성화 시 초점이 해당 인용으로 이동 | 스크롤만 되고 초점은 `body` |
| A12 | 확대 | 360px 폭에서 가로 스크롤 없음 | 발생 |
| A13 | 터치 표적 | 주요 조작 ≥ 44×44px | 미만 |

측정 방법: A4·A5 는 브라우저 개발도구의 대비 검사 또는 §2.1 표의 실측값. A7·A8·A11 은 스크린
리더(VoiceOver)로 확인. A3 는 `grep -rn "outline: *none" demo-ui/src`.

## 5. 문구와 톤

간결하고, 단정하고, 다음 행동을 말한다.

| 상황 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 근거 없음 | "관련 근거를 찾지 못했습니다 / 답변을 지어내지 않고 여기서 멈춥니다" | "결과가 없습니다" |
| 문서 없음 | "수집된 문서가 없습니다 / 문서를 먼저 올려 주세요" | "비어 있음" |
| 미인증 | "재시도해도 결과는 같습니다 — 자격증명이 있어야 합니다" | "오류가 발생했습니다" |
| 상한 초과 | "질의가 문자 수 상한(1,000자)을 넘었습니다" | "입력이 잘못되었습니다" |
| 삭제 확인 | "이 문서와 청크를 모두 지웁니다" | "정말요?" |
| 버튼 | "질문 보내기" · "삭제 확정" · "전문 펼치기" | "확인" · "여기" · "더보기" |

- 실패 문구는 **원인과 다음 행동**을 담아야 한다 (**MUST**).
- 재시도가 무의미한 실패는 그 사실을 말해야 한다 (**MUST**). 미인증 상태에서 "다시 시도해 보세요"
  는 거짓말이다.
- 서버가 주는 메시지가 이미 충분하면 그대로 쓴다. 덧씌워 뭉개지 않는다 (**MUST NOT**).

## 6. 안티패턴 — 금지

- **원시 값 직접 사용.** 컴포넌트 CSS 에 색상 코드나 새 px 간격을 적지 않는다. §2.5 의 예외 하나뿐.
- **초점 표시 제거.** `outline: none` 은 대체 표시가 있어도 쓰지 않는다.
- **검증 전 마커를 링크로 만들기.** 스트리밍 중 `[n]` 은 평문이다.
- **버려진 마커를 본문에서 지우기.** 흘러간 문장과 최종 문장이 달라진다.
- **답변 조각을 모아 한 번에 렌더.** 이 화면의 존재 이유를 지운다.
- **실패를 진행 중 상태로 남기기.** 종료 이벤트 없는 닫힘도 실패로 확정한다.
- **마지막 성공 헬스를 계속 표시.** 죽은 서버가 초록으로 보인다.
- **`window.confirm`·`alert`.** 스타일 불가, 스크린 리더 흐름 차단.
- **색만으로 상태 구분.**
- **서버에 없는 값 표시.** 캐시는 아직 구현되지 않았으므로 `cache_hit` 을 화면에 두지 않는다.
- **CDN 폰트 `@import`.** 조용한 폴백이 검증을 흔든다.
