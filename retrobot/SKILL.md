# Retrobot — 자동 회고 생성 스킬

> 이 문서는 AI 에이전트(Claude Code / Codex)가 읽고 실행하는 지침입니다.

## 목적

프로젝트의 AI 에이전트 작업 로그를 분석하여 **KPT(Keep/Problem/Try) 회고**를 자동 생성한다.
매 push마다 자동으로 실행되어, 성장의 흐름을 타임라인으로 기록한다.

## 실행 절차

### 1단계: 로그 탐색

현재 프로젝트의 AI 에이전트 작업 로그를 찾는다.

- **Claude Code:** `~/.claude/projects/` 아래에서 현재 프로젝트 경로(`git rev-parse --show-toplevel`)에 매핑되는 디렉토리를 찾는다. 경로의 **영숫자가 아닌 모든 문자**가 `-`로 인코딩되어 있다 — `/`뿐 아니라 `_`, `.`도 포함된다. (예: `/Users/foo/my_project` → `-Users-foo-my-project`)
- **Codex:** `~/.codex/` 아래 유사한 구조를 탐색한다.
- 로그 파일은 `*.jsonl` 형식이다.

로그를 찾지 못하면 "로그를 찾을 수 없습니다"라고 출력하고 종료한다.

### 2단계: 세션 분석

JSONL 로그는 한 파일이 수 MB에 이른다. **`Read`로 통째로 읽지 말고** `python3`(표준 라이브러리
`json`이면 충분하다)나 `jq`로 집계한 요약만 가져온다. 파싱 스크립트가 필요하면 `/tmp` 아래에
쓴다 — 리포지토리 안에 두면 미추적 파일이 남아 lint를 깨뜨린다.

#### 집계 도구가 없거나 막힌 환경 (먼저 확인할 것)

**이 훅은 샌드박스 안에서 돌고, 도구 가용성이 기계마다 다르다.** 아래 한 줄을 **먼저** 쳐서
무엇이 있는지 확정한다. 이 확인을 건너뛰면 매 회차 처음부터 우회로를 다시 찾게 된다
(실제로 열아홉 회차 반복됐다 — `retros/2026-08-03_1741_retro.md`).

```bash
command -v python3 jq
```

- **둘 중 하나라도 나오면** 그것으로 집계한다. 위 절차 그대로.
- **둘 다 없으면**(Windows 호스트에서 관측된 상태 — `python`·`py`·`python3`가 모두 Windows
  Store 별칭이라 exit 49로 죽고 `jq`도 없다) 셸을 더 시도하지 말고 **Claude Code 내장 도구만으로**
  집계한다. 아래가 그 절차다.

| 알고 싶은 것 | 도구 | 방법 |
|---|---|---|
| 대상 로그 파일 목록 | `Glob` | `~/.claude/projects/<인코딩된-경로>/*.jsonl` |
| 프롬프트 수 | `Grep` | `"type":"user"` 패턴, `output_mode: "count"` |
| 도구별 호출 수 | `Grep` | `"name":"<도구명>"` 패턴, `output_mode: "count"` — 도구마다 한 번 |
| 에러 수와 내용 | `Grep` | `is_error":true` / `Exit code`, `output_mode: "content"` + `-o` + `head_limit` |
| 세션 시작·종료 시각 | `Bash` | `head -n 8 <파일>` 과 `tail -c 130 <파일>` 로 **양 끝만** 뽑는다 |

**하지 말 것** — 이 환경들에서 전부 거부되거나 실패한 시도들이다.

- `python -c` / `node -e` 로 인라인 파싱 (인터프리터 자체가 없다)
- Bash heredoc, `/tmp`·`%TEMP%`에 스크립트 `Write` (샌드박스가 막는다)
- PowerShell 장문 명령 (약 965바이트에서 잘린다)
- `Grep`에 `output_mode: "content"`를 `head_limit` 없이 쓰기 (수 MB가 컨텍스트로 쏟아진다)

로그에서 다음을 추출한다:

- **사용자 프롬프트**: `type: "human"` 엔트리의 `message.content`
- **수행한 태스크**: 사용자 프롬프트 중 실질적인 작업 요청 (시스템 메시지, 태그 제외)
- **사용한 도구**: `type: "tool_use"` 또는 assistant 메시지 내 tool_use 블록
- **발생한 에러**: tool_result 중 error/failed/traceback 키워드 포함
- **세션 시간**: 각 세션의 시작/종료 타임스탬프

### 3단계: KPT 회고 작성

분석 결과를 바탕으로 아래 형식의 마크다운을 생성한다:

```markdown
# Retrobot 회고 — {날짜} {시간} KST

> 자동 생성된 회고입니다. 직접 편집하여 보완하세요.

## 요약

| 항목 | 값 |
|------|-----|
| 세션 수 | N |
| 총 프롬프트 | N |
| 에러 발생 | N |

## 세션별 활동

### 세션 `{id}` ({시작} ~ {종료})

**프롬프트:**
1. 실제 사용한 프롬프트 내용
2. ...

**발생한 에러:** (있는 경우)
- 에러 내용

## KPT 회고

### Keep (좋았던 것)
- 로그에서 파악한 긍정적 패턴 (에러 없이 완료, 효율적 도구 활용 등)

### Problem (나빴던 것)
- 반복된 에러, 비효율적 패턴, 실패한 시도 등

### Try (개선해야 할 것)
- Problem에 대한 구체적 개선 방안

## 타임라인

| 시각 | 세션 | 주요 활동 |
|------|------|----------|
| ... | ... | ... |
```

#### KPT 작성 가이드라인

- **Keep**: 단순 사실 나열이 아닌, "왜 좋았는지" 이유를 포함한다.
- **Problem**: 에러뿐 아니라 비효율(같은 작업 반복, 불필요한 시행착오)도 포함한다.
- **Try**: Problem 각각에 대응하는 구체적 액션 아이템을 제시한다.
- `<!-- 직접 추가하세요 -->` 플레이스홀더를 남겨 수동 보완을 유도한다.

### 4단계: 파일 저장

- 파일명: `retros/{YYYY-MM-DD}_{HHMM}_retro.md`
- `retros/TIMELINE.md` 테이블에 새 회고 링크를 추가한다.
- `retros/` 디렉토리가 없으면 생성한다.

### 5단계: Git 스테이징

- 생성된 `retros/` 내 파일을 `git add`한다.
- 커밋 메시지: `docs(retro): 자동 회고 생성 by Retrobot`

## 옵션

| 인자 | 설명 | 기본값 |
|------|------|--------|
| `--all` | 전체 세션 분석 | 최근 24시간만 |
| `--since {N}h` 또는 `{N}d` | 지정 기간 분석 | 24h |
